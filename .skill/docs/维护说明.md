## 版本号

- 当前发布版本：`1.1.0`
- 稳定调用名：`ppt-skill-v3`
- Runtime 包名：`ppt_skill_v3`

发布版本只用于 GitHub 同步、变更记录、安装检查和排障沟通，不等于 Skill 调用名或 schema 版本。当前 runtime 发布版本记录在 `.skill/scripts/runtime/ppt_skill_v3/__init__.py` 的 `__version__`；每次面向用户同步的更新，都应在 `.skill/CHANGELOG.md` 增加版本记录，写清新增、调整、兼容性和验收命令。

稳定标识边界：

- Skill frontmatter 的正式调用名是 `ppt-skill-v3`。

- Runtime Python package 使用 `ppt_skill_v3`。
- Schema title、schema id、项目恢复逻辑和本机密钥路径使用 `ppt-skill-v3` / `ppt_skill_v3` 口径。
- 当前工作区目录中的 `v3`、Skill frontmatter、agent metadata 和 runtime package 应保持同一正式标识。

历史和 legacy 口径：

- 历史项目状态中出现的 `v1`、`v2`、`v2.3` 或旧字段只作为 legacy 读取、迁移和 warning 线索，不作为新项目正式命名依据。

- 阶段3正式路线始终以 `阶段3逐字稿与教案输出规范.md` 为准：基于确认锁定稿输出逐字稿、Word、PDF，并按需输出 K12 教案。历史编辑重建路线只用于旧项目识别、迁移或排雷，不能作为新项目正式通过依据。

维护边界：

- 普通架构改造不得顺手重命名 `ppt-skill-v3`、`ppt_skill_v3`、schema id、密钥目录或旧项目状态字段。

## 主体识别

- 根目录存在且只存在 `AGENTS.md`：当前主体为 Codex。
- 根目录存在且只存在 `CODEBUDDY.md`：当前主体为 WorkBuddy。

WorkBuddy 形态下，根目录应只有：

WorkBuddy 的底座与 CodeBuddy Code 一致，自动加载的必读入口是 `CODEBUDDY.md`。因此识别到 WorkBuddy 运行或安装时，必须把根入口切换为 `CODEBUDDY.md`，不能只保留 `AGENTS.md`。

### 国际版 Canva 可编辑连接器

- `/canva`、`/可画` 均指国际版 Canva；当前 WorkBuddy 的可编辑路线是用户已启用并完成 OAuth 的 Canva MCP，Codex 的可编辑路线是 Canva 插件。
- `install-profile` 只切换 Skill 根入口，**不**安装连接器、不修改用户级 MCP 配置、不处理 OAuth 或 token，也不检查某个会话是否已暴露 Canva 工具。
- 每次实际编辑前由当前会话做工具/授权 preflight。WorkBuddy 缺少 `mcp__canva__*`、OAuth 失效或无设计编辑权限时，任务必须标为 connector 阻断或人工交接；不能假装改走 Codex 插件。
- Canva 的允许范围内文字与文字样式修订采用“默认 5 页一批，AI 主控逐页判断、审计留证、回读预览通过后直接 commit”策略；不等待用户逐批主动确认。此规则不是纯机械脚本，也不放宽 Magic Layers、字体族、背景、复杂图形、增删页面/内容等人工或不支持事项。
- token、签名导出 URL、签名缩略图 URL、本机路径都不得写入 task 记录、日志、发布包或变更记录。

## 输入输出规则

- 输入资料目录：`输入资料/`

- 禁止新建 `PPT输出/projects/`。
- 旧 `outputs/projects/` 只作为历史项目迁移线索，不作为新项目输出位置。

## 发布与 GitHub 边界

GitHub 仓库上传当前可维护源码和唯一维护入口，不上传本地输入资料、PPT 输出项目、打包产物 zip、缓存文件、测试目录或一次性过程产物。

发布包只包含普通用户运行 Skill 必要的入口、正式规范、模板、runtime、schema 和维护说明。

必须包含：

- `SKILL.md`
- `CHANGELOG.md`
- `agents/openai.yaml`
- `assets/`
- `references/`
- `scripts/`
- `docs/维护说明.md`

必须排除：

- `tests/`
- `docs/current/`
- `docs/archive/`
- `输入资料/`
- `PPT输出/`
- `inputs/`
- `outputs/`
- `tmp/`
- `dist/`
- `__pycache__/`、`.DS_Store`、`.pyc`、`.log`、`.tmp`、`.zip`

`docs/current/` 和 `docs/archive/` 是本地开发过程记录，不进入正式发布包；如未来要上传到 GitHub，只能作为开发历史处理，不能覆盖 `SKILL.md` 和正式 references 的当前口径。

## Windows/macOS 兼容

- macOS 路径示例：`/Users/<user>/Desktop/ppt-skill-v3（简易版）/PPT输出/<中文项目名>/`
- Windows 路径示例：`C:\Users\<user>\Desktop\ppt-skill-v3（简易版）\PPT输出\<中文项目名>\`
- 命令参数中的中文路径建议用引号包裹。
- 不在文件名中使用 Windows 禁止字符：`< > : " / \ | ? *`。
- 文件名不得以空格或点结尾。

## 中文路径与 UTF-8

- 所有 Markdown、JSON、manifest 和入口文档使用 UTF-8。
- JSON 写入必须保留中文，使用 `ensure_ascii=False`。
- 乱码排查先运行：

```bash
python3 .skill/scripts/pptctl.py inspect-installation
```

若终端中文显示异常，优先检查终端编码、Python stdout/stderr 编码和文件是否为 UTF-8。

## Poppler / pdftoppm

阶段4 PDF 图片派生只使用 `pdftoppm`，不新增其他 PDF 渲染备用路线。

- macOS 可通过 Homebrew 安装 Poppler。
- Windows 可使用 Poppler 官方包、Scoop 或 Chocolatey，并确保 `pdftoppm.exe` 在 PATH 中。
- 也可通过 `PPT_SKILL_PDFTOPPM` 指定可执行文件路径。

## 中文字体

- PDF/Word 渲染优先使用系统可嵌入中文字体。
- macOS 常见字体：Arial Unicode、系统补充字体。
- Linux 常见字体：Noto CJK、文泉驿。
- Windows 常见字体：微软雅黑、黑体、宋体。
- 可通过 `PPT_SKILL_CJK_FONT` 显式指定字体文件。

## 维护原则

- 不把测试、输入、输出、过程文档塞进普通用户发布包。
- 不恢复旧的文件整理类用户快捷入口。
- 不恢复已删除的用户说明文件。
- 不新增一套和 `PPT一致性.md`、`图片风格.md` 平行的风格权威。
- 旧项目兼容只能作为恢复线索，不作为新项目正式路线。
- Runtime 只做确定性检查，主控大模型保留审美、教学质量、内容取舍和返工判断。

## 常见故障

- 根目录同时出现 `AGENTS.md` 和 `CODEBUDDY.md`：运行 `install-profile --target codex` 或 `install-profile --target workbuddy`。
- 新项目跑到 `.skill/` 内：检查是否使用了旧命令或旧 cwd，正确命令以 `python3 .skill/scripts/pptctl.py` 开头。
- 新项目跑到 `outputs/projects/`：检查是否显式传入旧 `--output-root`，默认输出应为 `PPT输出/`。
- 旧项目根目录仍有 `_decisions/`：运行 `python3 .skill/scripts/pptctl.py migrate-decisions-layout --run-dir <项目目录>`，迁入 `_state/decisions/`。
- `输入资料/` 或 `PPT输出/` 下产物出现在 Git 状态里：重新运行当前 profile 安装命令，同步 `.git/info/exclude`。
- 中文 PDF 缺字：检查系统中文字体，必要时设置 `PPT_SKILL_CJK_FONT`。
