# 维护规划

本文是 PPT Skill v3 的发布维护规划入口，面向后续维护者和 GitHub 分发场景。正式业务执行仍以 `.skill/SKILL.md` 和 `.skill/references/` 为准；安装、版本、路径和排障细节见 `docs/维护说明.md`。

## 当前发布口径

- 当前发布版本：`1.0.4`
- 稳定调用名：`ppt-skill-v3`
- Runtime 包名：`ppt_skill_v3`
- 当前主体：Codex 使用根目录 `AGENTS.md`，WorkBuddy 使用根目录 `CODEBUDDY.md`。

## 发布包边界

发布包只包含普通用户运行 Skill 必要的入口、正式规范、模板、runtime、schema 和维护入口。

必须包含：

- `SKILL.md`
- `CHANGELOG.md`
- `agents/openai.yaml`
- `assets/`
- `references/`
- `scripts/`
- `docs/维护说明.md`
- `docs/维护规划.md`

必须排除：

- `tests/`
- `docs/current/`
- `docs/archive/`
- `输入资料/`
- `PPT输出/`
- `inputs/`
- `outputs/`
- `tmp/`
- `dist/`
- `__pycache__/`、`.DS_Store`、`.pyc`、`.log`、`.tmp`、`.zip`

## GitHub 同步边界

GitHub 仓库应上传当前可维护源码和正式维护入口，但不要上传本地输入资料、PPT 输出项目、打包产物 zip、缓存文件或一次性过程产物。

`docs/current/` 和 `docs/archive/` 是本地开发过程记录，不进入正式发布包；如需要上传到 GitHub，应仅作为开发历史处理，不能让它们覆盖 `SKILL.md` 和正式 references 的当前口径。

## 发布前检查

每次发布前至少执行：

```bash
python3 .skill/scripts/pptctl.py inspect-installation
python3 .skill/scripts/pptctl.py validate-style-templates
python3 .skill/scripts/pptctl.py validate-k12-subject-profiles
python3 /Users/yinxinhe/.codex/skills/.system/skill-creator/scripts/quick_validate.py .skill
PYTHONPATH=.skill/scripts/runtime:.skill/tests python3 -m unittest discover -s .skill/tests -v
python3 -m compileall -q .skill/scripts/runtime/ppt_skill_v3
python3 .skill/scripts/package_skill.py --output-dir .skill/dist
```

发布包生成后，还要核对 zip 与 manifest 文件清单一致，并确认 forbidden 项为 0。

## 维护原则

- 不把测试、输入、输出、过程文档塞进普通用户发布包。
- 不恢复旧的文件整理类用户快捷入口。
- 不恢复已删除的用户说明文件。
- 不新增一套和 `PPT一致性.md`、`图片风格.md` 平行的风格权威。
- 旧项目兼容只能作为恢复线索，不作为新项目正式路线。
- Runtime 只做确定性检查，主控大模型保留审美、教学质量、内容取舍和返工判断。
