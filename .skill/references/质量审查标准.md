# 质量审查标准

本文件保留详细质量检查项；QA、doctor、质量画像、主控判断和用户确认的职责分层以 `QA与doctor规范.md` 为准。

## 原则

质量审查分两层：

- 硬失败：真实性、确认点、目录边界、交付物存在、禁止 OCR 等红线问题。
- 主控判断：审美、信息密度、页面是否太花或太空、内页复杂度是否合适。

Runtime 只适合检查硬失败。主控大模型负责判断审美和返工路由。

阶段3逐字稿与教案检查属于主控判断辅助：它可以提示内容一致性、口播自然度、DOCX/PDF 可读性、K12 教案硬问题和 manifest 覆盖缺口，但不能单独把项目判为通过或失败。

## 硬失败

以下情况不能交付或进入下一确认点：

- 缺少用户对阶段1规划、阶段2封面风格或阶段2图片版 PDF 的确认。
- 正式图片不是来自选定的正式生图路线，或缺少 `codex_image_gen` / `openai_image_api` 对应 evidence。
- 同组多张图片没有按并发方式生成。
- fixture、本地渲染、source replay、HTML/canvas/SVG 冒充正式图片。
- 阶段3逐字稿或教案缺失，或 DOCX/PDF 不可打开。
- 阶段3逐字稿或教案引入与 PPT 冲突的新事实，且没有主控记录返工或风险说明。
- 阶段2或阶段3正式图的实际尺寸、目标尺寸或 `size_warnings` 缺失，导致清晰度风险不可追溯。
- 用户可见阶段目录混入 JSON、packet、日志、prompt 原稿等过程文件。
- 阶段1同时存在两个风格入口，或阶段2用户提示词文档存在坏链接、直接依赖未交付的 `_state` 附件、缺少当前正式图对应关系。
- 页数明显不一致或关键交付文件缺失。
- 阶段2B跳过试样直接生成全套正式图片，除非用户明确要求跳过。
- 试样未经用户确认就 promotion 到正式 `full_slide` results。
- 阶段2图片版 PDF 的 manifest 引用未确认试样、过期图片或缺少当前正式结果记录的 `img/` 文件。
- 阶段4整理生成占位文件、伪造缺失交付物，或把渲染失败的 PDF 图片当作成功。

## 主控判断

主控大模型判断：

- 风格是否合适。
- 四张封面是否在当前共同风格内体现不同构图与视觉重点。
- 用户选中的封面风格是否被扩展到内页。
- logo、标题、页码、章节标签和文字布局是否项目内统一。
- 用户未明确要求时是否没有可见页码；用户要求时页码是否统一。
- 普通内页顶部小标题是否使用同一具体位置、字体、颜色和装饰，组件是否在计划中解析一次。
- 多个模块介绍页是否使用同一具体结构，编号、标题和短说明是否只引用批准文字，没有后置重复追加。
- 专业型内页是否讲清楚。
- 演讲型内页是否足够简洁。
- 页面是否太花、太空或太满。
- 试样是否已经暴露整体视觉系统、版式语法或提示词问题。

## 阶段1

检查：

- 页数是否明确。
- 每页是否有清楚的信息目的。
- 每页是否有核心内容和辅助内容。
- 页面顺序是否有叙事逻辑。
- `PPT一致性.md` 是否存在，是否写清标题、模块页、页码、logo、公共元素、例外和禁用项。
- `图片风格.md` 是否存在，是否同时覆盖风格方向和图片提示词概要。
- `图片风格.md` 是否足够指导阶段2封面候选和后续图片生成。
- 是否没有把阶段1风格和图片提示词概要拆成两个正式用户可见文件。
- 是否符合用户目标和受众。
- 是否说明后续会先生成四张封面风格候选。
- `页面规划.md` 是否逐页写清最终可见中文文字、资料依据和内容保留边界。
- `每页干净逐字稿.md` 是否存在，是否逐页排版清楚，是否方便连续审阅每页内容。
- `每页干净逐字稿.md` 是否与 `页面规划.md`、`content.json`、`slide_prompt_briefs.json` 的每页最终可见文字一致。
- `design_contract.json` 是否写清路线、受众、资料边界、内容改写边界和封面候选策略。

## 阶段2A

检查：

- 图片来自真实正式生图路线：默认 `openai_image_api` 中转 API，或显式 `codex_image_gen`。
- 图片默认目标尺寸为 `1672x941`，实际尺寸、目标尺寸、目标容差、偏好底线和 `meets_target_size`、`meets_preferred_size` 已入账；低于 `1600x900` 的结果作为清晰度风险由主控判断。
- 比例按实际宽高单独核算：目标16:9，默认相对误差容差2%且包含边界；超出时保留原图和warning，由主控核对，不用最低宽高代替比例通过。字段与算法见 [生图证据链.md](生图证据链.md#尺寸和清晰度策略)。
- 四张封面共同配色、媒介、字体和禁用项一致，构图与视觉重点有实质差异。
- 四张封面是否基于 style card，有清晰差异、内页延展和风险说明。
- 用户可见目录提供封面图和同一份成功提示词文档；用户选择记录放在 `_state/阶段2/cover_options/selection/selection.json`，内部候选卡和请求记录不混入。
- 用户选择后已写入 `deck_style.json` 和 `layout_intent.json`。

## 阶段2B

检查：

- 图片来自真实正式生图路线：默认 `openai_image_api` 中转 API，或显式 `codex_image_gen`。
- 正式页面图和试样都按 `1672x941` 默认目标生成并保留尺寸记录；如低于 `1600x900` 优先底线或发生降采样，已作为清晰度风险记录。
- 试样和全量图执行与封面相同的独立比例检查；比例偏差、分辨率不足和文字不清分别报告。旧图缺比例字段时只读核算，不补造历史或自动撤销确认。
- 是否先展示总共5页试样并让用户确认，含已选封面，通常新生成4张内页；复杂页在名额内替换，短项目按实际页数。
- 试样通过后是否保留证据并 promotion 到正式结果。
- 试样失败时是否默认返工阶段2设计规划和提示词，而不是修改阶段1内容资产。
- 全套图片使用用户选中的视觉系统。
- 用户未明确要求时没有可见页码。
- 普通内页顶部小标题没有漂移。
- 模块介绍页像同一母版重复使用，没有随机换结构。
- 中文文字可读。
- 不出现英文占位、乱码、假字。
- 主视觉和页面主题一致。
- 每页之间风格统一。
- 新prompt是否只含横版画面要求、批准正文和必要限制；尺寸由参数设置，来源说明在代码块外；旧成功快照保持当时原文。
- 信息层级清楚。
- 图片不是纯装饰图。
- 如已记录 `_state/阶段2/visual_qa/stage2_aesthetic_review.json`，其中返工建议应指向正确范围。
- 图片版 PDF 可以打开。

阶段2轻量审美 QA 只抓明显问题：

- 视觉系统一致性。
- 文字可读性。
- 内容文字准确性。
- 页面角色匹配。
- 图片相关性。
- 无伪文字和占位符。
- 密度和层级。
- 页码默认关闭或按用户要求统一。
- 顶部小标题一致性。
- 模块介绍页一致性。

阶段2审美 QA 是主控提交用户确认前的轻量复核，不是自动视觉评分系统，不替代用户确认，也不让 runtime 自动判断审美。它的记录文件为：

```text
_state/阶段2/visual_qa/stage2_aesthetic_review.json
```

`review_scope` 只使用三个范围：`cover_options` 表示四张封面候选，`trial_first5` 表示阶段2B试样，`full_image_deck` 表示完整阶段2图片版。建议记录 `overall_status`、`review_scope`、关键检查项、逐页 findings 和 `rework_recommendation`；如果整体通过但仍有单页 finding 要求返工，必须把整体状态改成 `needs_rework`，不能写出自相矛盾的 QA。

返工路由按问题来源决定：封面候选整体不合适回 `stage2_cover`；已选封面可用但画面本身不可交付，回对应封面或 prompt；试样暴露视觉系统抽象错误，回 `stage2_design_plan`；普通页文字不清、构图跑偏或图片无关，回 `stage2_prompt` 或 `selected_slides`；未请求却出现页码、页码不统一、顶部标题漂移、模块页骨架漂移，先回阶段2设计来源，更新 `图片风格.md`、deck/layout 组件和受影响页 `image_prompt_plan`，再重新派发完整 prompt。

试样确认不替代图片版 PDF 确认。图片生成成功不等于审美 QA 通过，审美 QA 通过也不等于用户已经确认阶段2图片版 PDF。质量判断必须说明返工范围、可接受残余风险或继续等待用户确认。

阶段2审美 QA 禁止事项：

- 不做像素级自动评分。
- 不要求每页完美。
- 不因轻微对齐差异阻断用户确认。
- 不让 runtime 自动判断审美。
- 不把试样确认当成最终图片版 PDF 确认。
- 不为省 token 强行复用有明显文字、构图或证据问题的已选封面。
- 不在既有 prompt 末尾反复追加“其余不变”，应回到来源计划修正后重新派发。

## 阶段3

检查：

- 阶段3锁定稿来源已由用户确认；来源可以是阶段2图片版 PDF，或用户确认的外部 PPTX/PDF。
- `speaker_script.json` 全局只保留演讲标题和讲者身份，每页只保留页码、页面标题和逐字稿。
- 逐字稿不是页面文字照读版；每页内容自然、通顺、足够展开，且没有引入与 PPT 冲突的新事实。
- 如用户要求调研补充、页面内容明显偏薄，或主题属于高准确性场景，已按内容需要使用权威来源校准口径，并在 `_state/阶段3/`、manifest 或阶段决策中记录来源用途；不要为了完成流程堆来源。
- Word 版存在、可打开、使用结构化样式、第一页顶部题头、页眉页脚、中文字体与语言属性，以及每页讲稿区块；没有单独封面页。
- PDF 版存在、可打开、文字可选择，不是整页图片拼接，内容与 Word 来自同一份讲稿数据，并优先嵌入中文字体。
- Word/PDF/Markdown 逐字稿文件名使用 `<封面第一页主题>｜逐字稿`，没有退回 `演讲逐字稿.*` 这类固定旧名。
- Word/PDF 无明显截断、重叠、乱码、孤立标题或表格溢出。
- PDF 已抽查第一页、中间页和末页渲染图，确认第一页题头后直接进入第 01 页内容；DOCX 已用系统预览/Word/WPS 或 XML/文本抽取等方式确认中文内容未丢失。
- `_state/阶段3/speaker_script_manifest.json` 记录 DOCX/PDF 路径、sha、PDF 生成工具和检查状态。
- 如有返工，返工阶段和原因明确。

K12 教案设计额外检查：

- K12 触发条件明确；只说“课件”但缺学段、年级、教材、学科等信号时，不能直接标记 `education_context.is_k12=true`。
- `education_context` 已记录或可从阶段1资产恢复，能支撑学段/年级、学科和课题等核心判断；无法确认的课时、教材版本、班级等不写入教师可见正文。
- `_state/阶段3/lesson_plan_context.json` 只在材料较多、来源冲突或旧项目缺少教育上下文时按需生成，不作为阶段3必经大文件。
- `lesson_plan.json` 或等价薄输入由主控撰写，不能把教案结构塞进 `speaker_script.json`。
- 教案活动不能修改 PPT 页面、页数或阶段1已确认内容；发现阶段1与教材冲突时，必须写入 `source_conflicts` 和教师确认项。
- 每个核心教学环节在内部能追溯到 PPT 页码或教材材料；教师可见过程表不把“时间”“PPT/材料”做成机械固定列。
- 教学目标、课堂活动和评价证据有对应关系。
- 教学方案应呈现课堂任务链，核心环节有关键提问、追问纠偏、学生产出和评价证据；如果只是“教师讲解、学生回答”的短提纲，由主控扩写修订，不交给 runtime 硬判。
- 板书设计应支撑课堂讲解、总结和学生复盘，体现知识结构、问题链、方法链、证据链或易错点；只有关键词堆砌时由主控扩写修订。
- 科学、物理、化学、生物等实验活动必须包含器材、步骤、现象/结论和安全提示；化学还应关注药品、方程式和废弃物处理。
- 教学反思不得伪造真实课后事实；无用户反馈时只能输出反思预案或待填写项，并给出课堂观察、问题诊断、调整策略和二次备课记录方向。
- K12 教案不以页数定质量；PDF 页数只记录排版结果，不因低页数或高页数自动 warning、失败或补写。
- 教案 Word/PDF 可打开、文字可选择、中文不乱码，不是整页图片拼接；不得因强制分页导致标题或短块内容单独占页形成大面积空白。
- `lesson_plan_manifest.json` 记录 Markdown/DOCX/PDF 路径、sha、页数、渲染模式、学科组、PDF 文本探测和 Word 表格模式；完成前 manifest 状态应为 `generated`。
- `lesson_plan_qa.json` 如生成，只作为主控自审记录；阶段3完成看是否存在硬问题。普通 warning、材料缺口和教师课前调整项应记录在 `_state/阶段3/lesson_plan_qa.json`、manifest 或阶段决策中。

## 阶段4

检查：

- 主题文件夹位于 `阶段4_文件整理交付/<主题名称>/`，没有放在项目根部，也没有额外套 `最终交付/`。
- `图片素材/` 只复制阶段2正式页面图 `slide_*.png`，不混入封面候选、试样、QA 预览或 `_state` 图片。
- `每页干净逐字稿.md` 来自阶段1确认目录。
- `<主题名称>｜图片版PPT.pdf` 来自阶段2图片版 PDF。
- `<主题名称>｜逐字稿.docx` 与 `<主题名称>｜逐字稿.pdf` 来自阶段3逐字稿输出。
- K12 项目如已有阶段3教案 DOCX/PDF，应复制为 `<主题名称>｜教案设计.docx/pdf`。
- 非 K12 项目、教案缺失或教案 PDF 渲染失败时，不创建教案占位文件或空的教案图片目录。
- 不复制历史编辑稿到标准整理目录。
- 阶段3逐字稿 PDF 存在时，`逐字稿图片/page_*.png` 由 `pdftoppm -png -r 216 -forcenum` 从整理后的 PDF 派生。
- K12 阶段3教案 PDF 存在时，`教案设计图片/page_*.png` 由同一路线派生。
- 找不到 `pdftoppm`、PDF 损坏或渲染失败时，不阻塞其他复制；失败项必须记录在 skipped 中。
- 不生成空文件、占位文件或交付清单来冒充缺失产物。
- 整理 summary 或 manifest 记录复制、渲染和 skipped 项。
