# 阶段流程

本文件只定义 PPT Skill 的正式阶段顺序、阶段产物和进入条件；跨阶段红线以 `核心不变量.md` 为准，恢复和防漂移动作以 `恢复与防漂移协议.md` 为准。

## 总流程

```text
阶段0_资料整理
-> 阶段1_规划确认
-> 阶段2_图片版PPT
-> 阶段3_逐字稿与教案输出
-> 阶段4_文件整理交付
```

阶段规范是软导航，不是代码硬门禁。大模型负责判断是否继续、返工、暂停或完成；runtime 只能执行主控明确放行的确定性动作。阶段切换必须写入主控 decision，不能由文件存在、状态字段或脚本默认规则自动触发。

## 阶段外 Canva 辅助编辑任务

`/canva`、`/可画` 都是国际版 Canva 的阶段外辅助任务，不属于阶段0到阶段4主流程。WorkBuddy 首选 Canva MCP，Codex 首选 Canva 插件；两者都由 AI 主控按同一份逐页执行卡理解页面角色、完成逐字稿校验、处理 Magic Layers 人工节点、回读预览并直接 commit，阶段边界统一见 [Canva辅助编辑任务规范.md](Canva辅助编辑任务规范.md)。

Canva 辅助结果不自动算阶段完成。用户后续明确确认 Canva 导出稿可作为锁定稿时，它只能作为阶段3逐字稿/教案输出的外部锁定稿来源。

## 阶段0：资料整理

目标：整理输入，不做正式规划。

主控大模型：

- 理解用户目标。
- 选择项目名；如果用户在发起或确认项目时提供明确编号、序号或项目代号，项目名使用 `<用户编号> <主题>`，不自动把编号写入 PPT 可见文字。
- 整理资料清单和资料摘要，资料可以包括 PPT/PPTX、Word/DOCX、PDF、截图、表格、讲稿、文本和用户聊天口径。
- 判断资料是否足够进入阶段1。
- 当用户要求把微信公众号文章、截图、PDF 或复制全文作为主资料来复刻、完整提取、仿写或改造成 PPT 时，按 `阶段0微信公众号资料处理规范.md` 生成完整资料包；图片文字必须逐图完整提取，不得用摘要代替 OCR 原文或跳过小字、表格、图注和流程节点。

阶段0产物：

- `输入资料/<项目名>/` 中的源资料入口副本（文件资料）
- `阶段0_资料整理/资料清单.md`
- `阶段0_资料整理/资料摘要.md`
- `_state/阶段0/materials_index.json`
- `_state/阶段0/原始资料/`
- `_state/阶段0/提取文本/`
- `_state/阶段0/网页资料/`（可选）

禁止：

- 不生成正式页面规划。
- 不生成正式页数和逐页标题。
- 不生成每页最终可见文字。
- 不生成正式图片提示词。
- 不开始生图。
- 不只把文件资料藏进 `_state/阶段0/原始资料/`；文件资料必须同步保留在工作区根目录 `输入资料/<项目名>/`，`_state` 里的是项目归档副本。

## 阶段1：规划确认

目标：由主控大模型基于阶段0资料和用户目标写规划，让用户确认。阶段1最重要的是把每页最终可见文字定死，后续阶段2生图和阶段3逐字稿/教案都继承同一份内容资产。

阶段1必须先整合所有资料，再写 `页面规划.md`。不能按单一文件机械拼页；如果同时有 PPT、Word、PDF、截图和用户补充口径，主控大模型要判断主材料、补充材料、冲突处理和内容取舍。

产物：

- `阶段1_规划确认/页面规划.md`
- `阶段1_规划确认/每页干净逐字稿.md`
- `阶段1_规划确认/PPT一致性.md`
- `阶段1_规划确认/图片风格.md`
- `_state/阶段1/design_contract.json`
- `_state/阶段1/layout_safety_contract.json`
- `_state/阶段1/content.json`
- `_state/阶段1/slide_prompt_briefs.json`

`content.json` 是阶段1正文唯一权威来源。`页面规划.md` 是由该正文同步的逐页规划表，必须包含页码、页面角色、页面标题、页面目的、最终可见中文文字、资料依据、内容保留边界和视觉意图；正文不应在规划表中独立修改后生效。

`每页干净逐字稿.md` 是阶段1给用户审阅内容的逐页阅读稿。它必须逐页呈现最终可见中文文字，不能新增 `页面规划.md` 和 `content.json` 之外的页面文字。

`PPT一致性.md` 是阶段1用户可见的版式秩序文档，必须写清标题统一、模块页统一、公共元素、例外和一致性禁用项。`图片风格.md` 是阶段1用户可见的视觉气质和提示词方案文档，必须写清当前生效风格、风格禁用项、不同页面的应用和逐页图片规划。

进入阶段2条件：

- 主控大模型检查规划完整。
- `页面规划.md`、`每页干净逐字稿.md`、`content.json`、`slide_prompt_briefs.json` 的每页可见文字一致。
- `design_contract.json` 与 `layout_safety_contract.json` 已写入。
- 用户确认阶段1四份真实材料：`页面规划.md`、`每页干净逐字稿.md`、`PPT一致性.md`、`图片风格.md`。
- 写入 `approve_stage1_start_stage2` 主控决策。

## 阶段2A：封面风格候选

目标：基于阶段1 `design_contract.json` 在当前图片风格范围内生成四张有构图差异的封面图，让用户选择整套 PPT 的视觉方向。

生成要求：四张封面默认走 `openai_image_api` 国内直连中转路线；用户明确指定或主控判断需要时，可走 `codex_image_gen` 官方备用路线。两条路线都必须记录 batch、对应路线 evidence、结果 ID、图片 sha、实际尺寸、目标尺寸、容差和必要 warning。默认目标尺寸为 16:9 `1672x941`，允许生成器返回存在轻微尺寸差异；优先底线为 `1600x900`，尽量保留生成原始 raster，不主动降采样或压缩。

产物：

- `阶段2_图片版PPT/封面风格候选/cover_option_A.png`
- `阶段2_图片版PPT/封面风格候选/cover_option_B.png`
- `阶段2_图片版PPT/封面风格候选/cover_option_C.png`
- `阶段2_图片版PPT/封面风格候选/cover_option_D.png`
- `_state/阶段2/cover_options/style_cards/`

进入阶段2B条件：

- 用户确认封面风格。
- 主控大模型检查并写入视觉系统和版式意图。
- 写入 `approve_stage2_cover_style_start_image_deck` 主控决策。

## 阶段2B：试样、整页图片与图片版 PDF

目标：按阶段1逐字稿生成带中文文字的整页图片，并打包为图片版 PDF。阶段2生成的是后续输出的锁定视觉母版。

生成要求：阶段2B图片默认走 `openai_image_api` 国内直连中转路线；用户明确指定或主控判断需要时，可走 `codex_image_gen` 官方备用路线。两条路线都必须按 `execution_group` 建 batch manifest，并记录对应路线 evidence、结果 ID、实际尺寸和图片 sha。

阶段2 prompt 必须继承：

- 阶段1逐字稿，只能使用 `content.json` 中确认过的最终可见文字；`slide_prompt_briefs.json` 的文字字段是可验证派生物，不能覆盖 `content.json`。
- `layout_safety_contract.json` 的文字区、图像区和禁压区。
- 项目 `PPT一致性.md` 中本页适用的标题、模块页、公共元素、例外和禁用项。
- 已锁定的 `deck_style.json` 和 `layout_intent.json`。

内部流程：

```text
先把可用的已选封面候选转正为正式封面页
-> 生成阶段2B试样
-> 用户确认视觉、文字、密度和风格方向
-> 试样通过后生成剩余页面
-> 全套正式页面图齐全后打包图片版 PDF
```

产物：

- `阶段2_图片版PPT/图片生成提示词.md`（封面、试样、全量三次交付均提供）
- `阶段2_图片版PPT/img/slide_001.png ...`
- `阶段2_图片版PPT/pdf/<封面第一页主题>｜图片版PPT.pdf`
- `_state/阶段2/visual_qa/stage2_aesthetic_review.json`

进入阶段3条件：

- 主控大模型检查图片质量，并可记录阶段2轻量审美 QA。
- 用户确认图片版 PDF。
- 写入 `approve_stage2_start_stage3` 主控决策。

## 阶段3：逐字稿与教案输出

目标：基于用户确认的锁定稿生成 PPT 演讲逐字稿，并输出 Markdown、Word 和同源 PDF。K12 课件项目在同阶段输出教案设计 Markdown、Word 和 PDF。

阶段3锁定稿来源：

- `stage2_image_deck`：阶段2图片版 PDF。
- `external_locked_deck`：用户确认的外部 PPTX 或 PDF，例如 Canva 最终导出稿。

阶段3不能修改 PPT 页面、页数、页面结论或阶段1已确认内容。外部锁定稿只作为阶段3输入，不反写阶段2完成状态。

阶段3内部流程：

```text
确认锁定稿来源
-> 主控撰写 speaker_script.json
-> 生成用户可读 `<封面第一页主题>｜逐字稿.md`
-> 生成专业排版 Word
-> 生成同源 PDF
-> K12 项目按需形成教育上下文和 lesson_plan.json
-> K12 项目生成教案 Markdown、Word、PDF
-> 主控检查内容、文件可读性和 manifest
-> 记录 `stage3_outputs_completed`，进入阶段4整理
```

产物：

- `阶段3_逐字稿与教案输出/逐字稿/<封面第一页主题>｜逐字稿.md`
- `阶段3_逐字稿与教案输出/逐字稿/<封面第一页主题>｜逐字稿.docx`
- `阶段3_逐字稿与教案输出/逐字稿/<封面第一页主题>｜逐字稿.pdf`
- K12 项目额外生成：
  - `阶段3_逐字稿与教案输出/教案设计/<封面第一页主题>｜教案设计.md`
  - `阶段3_逐字稿与教案输出/教案设计/<封面第一页主题>｜教案设计.docx`
  - `阶段3_逐字稿与教案输出/教案设计/<封面第一页主题>｜教案设计.pdf`
- `_state/阶段3/speaker_script.json`
- `_state/阶段3/speaker_script_manifest.json`
- K12 项目额外生成 `_state/阶段3/lesson_plan.json`、`lesson_plan_manifest.json`；`education_context.json`、`textbook_context.json`、`lesson_plan_context.json` 和 `lesson_plan_qa.json` 按需作为辅助或自审记录生成

逐字稿要求：

- 每页必须绑定 PPT 页码、页面标题和逐字稿正文。
- 逐字稿要适合真实口播，不只是照读页面文字；每页可以自然展开得更详实，但不能写成机械说明书或资料堆砌。
- 用户要求调研补充、页面内容明显偏薄，或主题属于医学、护理、法律、财务、政策等高准确性场景时，可用权威来源校准口径和补足背景，并把来源用途记录到 `_state/阶段3/`。
- 逐字稿不能引入和 PPT 冲突的新事实。
- Word 使用结构化样式、第一页顶部题头、页眉页脚、中文字体与语言属性，以及每页讲稿区块；不要设置单独封面页。
- PDF 与 Word 使用同一份讲稿数据，文字可选择，优先嵌入中文字体，不用图片拼接冒充。
- K12 教案由主控撰写，runtime 只做结构校验、渲染、路径入账和可见文本清洁检查；教案不得修改 PPT 页面或阶段1已确认内容。

进入阶段4条件：

- 主控确认逐字稿 Markdown、Word、PDF 已生成且可读。
- K12 项目必须同时确认教案 Markdown、Word、PDF 已生成且无硬问题。
- Manifest 记录真实路径、sha、页数或文本检查状态。
- 写入 `stage3_outputs_completed` 主控决策。

用户提出修改时，由主控大模型判断返工到阶段3、阶段2或阶段1。

## 阶段4：文件整理交付

目标：把当前项目中识别到且实际存在的交付物整理到 `阶段4_文件整理交付/<主题名称>/` 文件夹，并把已存在的阶段3逐字稿 PDF 确定性派生成 PNG 图片副本；K12 教案 PDF 已存在时，同样用 `pdftoppm` 派生教案 PNG 副本。

阶段4只整理和派生，不生成新的 AI 图片、PPT、逐字稿或教案。整理器是阶段4内部 runtime 动作，可在阶段3完成后由主控建议执行；但整理器本身不写阶段切换 decision。

输入：

- `阶段1_规划确认/每页干净逐字稿.md`
- `阶段2_图片版PPT/img/slide_*.png`
- `阶段2_图片版PPT/pdf/<封面第一页主题>｜图片版PPT.pdf`
- `阶段3_逐字稿与教案输出/逐字稿/<封面第一页主题>｜逐字稿.docx`
- `阶段3_逐字稿与教案输出/逐字稿/<封面第一页主题>｜逐字稿.pdf`
- K12 项目可选：阶段3教案 DOCX/PDF

基础输出：

```text
阶段4_文件整理交付/
  <主题名称>/
    图片素材/
      slide_001.png
      slide_002.png
    逐字稿图片/              # 仅逐字稿 PDF 存在且渲染成功时创建
      page_001.png
      page_002.png
    每页干净逐字稿.md
    <主题名称>｜图片版PPT.pdf
    <主题名称>｜逐字稿.docx
    <主题名称>｜逐字稿.pdf
```

K12 项目且阶段3教案 DOCX/PDF 已存在时，额外纳入：

```text
阶段4_文件整理交付/
  <主题名称>/
    教案设计图片/            # 仅教案 PDF 存在且渲染成功时创建
      page_001.png
      page_002.png
    <主题名称>｜教案设计.docx
    <主题名称>｜教案设计.pdf
```

PNG 派生规则：

- 只渲染整理目录里已经存在的逐字稿 PDF；K12 教案 PDF 存在时才渲染教案 PDF。
- 只使用 `pdftoppm -png -r 216 -forcenum`，对应 `216 DPI / 3x_72dpi`。
- 输出文件固定为 `page_001.png`、`page_002.png`。
- 找不到 `pdftoppm`、PDF 损坏或渲染失败时，只在整理摘要中记录 skipped，不阻塞其他文件复制。

阶段4完成条件：

- 整理 manifest 或 JSON 摘要记录本次复制、渲染和 skipped 项。
- 主控确认整理结果符合 `阶段4整理交付规范.md`，没有把缺失文件伪造成交付物。
- 写入 `stage4_deliverables_organized` 主控决策，项目进入 completed。
