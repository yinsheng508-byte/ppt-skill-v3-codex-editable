# 交付文件命名规范

## 命名目标

阶段2、阶段3和阶段4的用户可交付文件必须能从文件名看出主题和类型，避免多个项目都叫 `图片版PPT.pdf`、`逐字稿.docx` 或 `教案设计.pdf`。

## 主题来源

交付文件名前缀取“封面第一页上的主题”。主控在阶段1必须把这个主题稳定写入：

- `_state/阶段1/content.json` 的 `deck_title`。
- 第 1 页或封面页的最终可见主标题，通常是 `slides[0].final_visible_text[0]`。
- `页面规划.md` 和 `每页干净逐字稿.md` 中第 1 页对应的封面主标题。

如果封面页的页面标题只是“封面”“首页”“标题页”等泛化名称，不得拿它当文件名前缀；应使用封面可见主标题或 `deck_title`。如果阶段1内容资产暂不可用，runtime 可以用项目名兜底，但主控交付前应按封面主题修正。

## 用户编号

用户在发起或确认 PPT 项目的对话中提供明确编号、序号或项目代号时，主控必须把该编号保留到项目命名和交付文件名前缀中，便于用户按编号统计 PPT 进度和交付情况。

- 项目目录名使用 `<用户编号> <主题>`，例如 `03 水循环`、`TBH-012 鸦片战争`。
- 阶段2、阶段3和阶段4的主题化交付文件名前缀同步使用 `<用户编号> <封面第一页主题>`。
- 编号只用于项目目录和交付物命名；不要因为命名编号自动修改封面标题、`deck_title`、页面可见文字或逐字稿正文。用户明确要求编号出现在 PPT 内容中时，才写入可见文字。
- 如果用户只给编号、主题仍由主控根据资料判断，先使用主控判断的主题组成项目名；后续用户修正主题时，主控应同步修正项目名和后续交付文件名前缀。
- 不得自行编造编号。用户没有提供编号时，继续使用纯主题命名。

## 标准文件名

`<命名前缀>` 默认等于封面第一页主题；用户提供明确编号时，等于 `<用户编号> <封面第一页主题>`。

阶段2图片版 PDF：

```text
阶段2_图片版PPT/pdf/<命名前缀>｜图片版PPT.pdf
```

阶段3逐字稿：

```text
阶段3_逐字稿与教案输出/逐字稿/<命名前缀>｜逐字稿.md
阶段3_逐字稿与教案输出/逐字稿/<命名前缀>｜逐字稿.docx
阶段3_逐字稿与教案输出/逐字稿/<命名前缀>｜逐字稿.pdf
```

阶段3 K12 教案设计：

```text
阶段3_逐字稿与教案输出/教案设计/<命名前缀>｜教案设计.md
阶段3_逐字稿与教案输出/教案设计/<命名前缀>｜教案设计.docx
阶段3_逐字稿与教案输出/教案设计/<命名前缀>｜教案设计.pdf
```

阶段4文件整理主题文件夹中的交付副本：

```text
阶段4_文件整理交付/<命名前缀>/每页干净逐字稿.md
阶段4_文件整理交付/<命名前缀>/图片素材/slide_001.png
阶段4_文件整理交付/<命名前缀>/逐字稿图片/page_001.png
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜图片版PPT.pdf
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜逐字稿.docx
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜逐字稿.pdf
```

K12 项目且阶段3教案 DOCX/PDF 已存在时，主题文件夹中额外纳入：

```text
阶段4_文件整理交付/<命名前缀>/教案设计图片/page_001.png
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜教案设计.docx
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜教案设计.pdf
```

主题文件夹直接位于 `阶段4_文件整理交付/` 下，不再放在项目根部，也不再额外套 `最终交付/`。阶段3逐字稿 Markdown、教案 Markdown 和各类说明文件不进入阶段4主题文件夹。`逐字稿图片/` 只在逐字稿 PDF 存在且渲染成功时创建；`教案设计图片/` 只在 K12 教案 PDF 存在且渲染成功时创建。两个图片目录只放由同目录 PDF 确定性渲染出的 `216 DPI / 3x_72dpi` PNG，文件名固定为 `page_001.png`、`page_002.png`。

阶段4标准整理结构不包含历史编辑稿。外部编辑稿如需保留，必须作为用户额外要求处理，不进入默认主题文件夹。

## 清理规则

文件名前缀要保留用户编号和中文主题本身，但必须清理会破坏文件路径或造成歧义的字符：

- 把 `/ \ : * ? " < > |`、控制字符和换行替换为空格。
- 把全角分隔符 `｜` 从主题里移除，分隔符只由命名模板添加一次。
- 合并连续空格，去掉首尾空格、点号、下划线和横线。
- 主题过长时可以截短到可读范围，保留能识别项目主题的前半部分。

## 兼容旧项目

旧项目里已经存在的固定名 `图片版PPT.pdf`、`演讲逐字稿.md`、`演讲逐字稿.docx`、`演讲逐字稿.pdf`、`教案设计.md`、`教案设计.docx`、`教案设计.pdf` 可以继续作为恢复和校验候选，不能因此判定项目损坏。

旧项目历史编辑稿只能作为兼容读取线索，不是新阶段模型的标准交付文件。新生成、新入账和新交付一律使用主题化命名。manifest、`project_state.user_artifacts`、`project_state.expected_user_paths` 和主控决策中的 `confirmed_files` 必须记录真实路径，不要继续写旧固定名。
