# PPT一致性文档规范

本文规定主控如何在每个具体项目的阶段1写 `PPT一致性.md`。它是写法规范，不是项目实例，也不直接进入生图 prompt。

项目里的实际文档固定放在：

```text
阶段1_规划确认/PPT一致性.md
```

阶段2自动生成每页图片提示词时，读取的是项目里的 `PPT一致性.md` 和 `图片风格.md`。`PPT一致性.md` 管版式秩序，`图片风格.md` 管画面气质。两份文档都要在阶段1交给用户确认。

用户选择封面后，主控会把选中的封面方向沉淀为内部执行资产 `_state/阶段2/deck_style.json`。其中和标题区、模块页、页码、logo、页眉页脚、公共视觉家具有关的规则，必须能回到项目 `PPT一致性.md` 找到用户可见依据；不能让 `deck_style.json` 成为第三份会反向改写阶段1文字的权威。

## 写作原则

`PPT一致性.md` 必须写成具体、可检查的规则，不能停留在“保持统一、简洁高级、风格一致”。文档整体应说明适用页面、固定元素、允许变化和例外边界；不要求把同一个意思拆成大量重复条目。

主控可以使用比例、方位、层级、颜色角色、字体角色和参考页描述规则；这些值是生图构图目标，不等于原生 PPT 母版坐标。若需要绝对字体和坐标一致，应另走确定性排版或母版路线。

`PPT一致性.md` 不得新增阶段1未确认的页面文字。标题、模块编号、模块标题和短说明都必须来自 `页面规划.md`、`每页干净逐字稿.md`、`content.json` 和 `slide_prompt_briefs.json` 已一致的内容。

## 固定结构

项目文档使用以下五个二级标题。标题名称保持一致，便于 runtime 读取适用规则。

```markdown
# PPT一致性

## 标题统一

## 模块页统一

## 全套公共元素

## 不适用与例外

## 统一禁用项
```

可以在每个二级标题下增加三级标题或表格，但不要改二级标题名称。`调整记录` 可以作为最后一个二级标题记录历史变化，历史记录不参与新提示词编译。

## 标题统一

本节写普通内容页、流程页、图表页、案例页等同类内页的标题组件规则。至少说明：

- 适用页面：列出使用普通标题组件的页面角色。
- 标题语义：说明这里的标题只指当前页页面标题，默认不另设章节导航标签。
- 位置与容器：说明标题靠左上、左边距、顶部留白、标题区宽高、最多行数。
- 字体层级：说明字体气质、字号档位、字重、颜色角色、行距和对齐。
- 装饰与避让：说明标题下划线、角标、图标、分隔线是否固定，以及正文从哪里开始。
- 长标题处理：说明两行标题、语义换行、无法容纳时回到阶段1处理，不允许单页任意缩字或删词。
- 允许变化：通常只允许替换本页已确认标题文字。
- 例外：列出不使用普通标题组件的页码、角色和替代规则。

推荐表达：普通内容页使用同一左上标题组件。除本页已确认标题文字外，标题位置、容器范围、字体、字号、字重、颜色、对齐、行距、装饰和正文安全距离保持一致。封面、模块页、结束页和已登记特殊页按各自角色模板处理。

标题组件是提示词计划来源。准备 `image_prompt_plan` 时，主控把标题位置、字体、装饰和安全区归并到 `layout`；正式编译时不再后置追加一份原始标题片段。标题文字通过 `text_roles.title` 引用已批准正文，不从内部页序、brief 标题或上一页描述补字。

章节标签、眉题或模块导航条不是普通内容页默认标题组件。只有用户或项目规则明确要求启用，且该标签文字已经进入批准正文并有明确角色绑定与安全区时，才可作为单独组件描述；否则不得把跨页章节映射表、模块名示例或 `header_policy` 自然语言补成可见标签。模板或规范示例不得默认写“标题上方另设章节标签”。

## 模块页统一

本节写章节页、模块介绍页或单元过渡页的统一骨架。只有项目实际使用模块页时才填写具体模板；没有模块页时写明“本项目无模块页，不使用模块页模板”。

项目有多个同级模块页时，至少说明：

- 模块层级：说明当前模块页属于章、节、活动环节还是其他层级。
- 编号规则：说明编号体系、编号容器、位置和文字层级。
- 标题规则：说明模块标题位置、容器、对齐、行数和字体层级。
- 短说明规则：说明是否有一行短说明、放在哪里、最多几行。
- 主视觉槽位：说明主视觉位置、比例、媒介和是否允许主题变体。
- 背景与装饰：说明底色、纹理、分隔线、符号和节奏。
- 允许变化：只允许替换已确认的模块编号、模块标题和规定短说明；其他变化必须预先写清。
- 基准页：如已有试样或同类页，说明对照哪一页。

同级模块页必须像同一模板的连续使用，不得每页随机改变编号形状、标题对齐、人物比例、主视觉位置或背景语言。

模块页模板同样是计划来源。模块编号、模块标题和短说明必须来自已批准正文并通过 `text_roles` 引用；模板只负责容器、位置、层级、分隔线、主视觉槽位和背景节奏。同类模块页不能只写“沿用上一页”，每页 prompt 都要包含本项目已经确定的具体骨架。

## 全套公共元素

本节写全套 PPT 需要稳定出现或稳定不出现的公共元素。至少检查：

- 页码：默认不显示可见页码；如用户明确要求显示，说明位置、样式、适用页和豁免页。最终生图中的页码仍由 `page_number_policy` 单独处理，不能在单页画面计划里重复写一份页码规则。
- logo：只有用户提供真实授权资产且明确需要时才出现，并写清位置、尺寸和留白。
- 页眉页脚、角标、底线、图标、容器、箭头、线宽、圆角、阴影等视觉家具；章节标签仅在明确 opt-in 时列入视觉家具，不能默认加到普通页。
- 字体角色：页标题、模块标题、正文、强调数字、注释的层级关系。
- 颜色角色：背景、标题、正文、强调、警示、数据分类的稳定含义。
- 图像和证据素材：插画、摄影、截图、图表、医学影像等各自的容器和保真边界。

公共元素要说明“什么时候出现、怎么出现、什么时候不出现”。不要因为追求统一而给用户未要求的页面强行加 logo、页码或装饰文字。

### 页码策略

可见页码默认关闭。主控只有在用户明确要求“加页码、显示页码、保留页码”等含义时，才启用 `deck_style.page_number_policy.enabled=true`，并写清 `position`、`style`、`applies_to` 和 `exclude_slide_indices`。未填写 `applies_to` 时，页码只适用于非封面页面；封面默认豁免，除非用户明确要求封面也显示页码并把 `cover` 纳入适用范围。

不要把 `页面规划.md` 里的页序、内部索引或资料页码画进页面。编译器只依据已确认的 `page_number_policy` 生成一次页码指令；`image_prompt_plan.visual/style/layout/constraints` 不再重复写页码规则。若 `text_roles.page_number` 引用批准正文中已有页码，只安排该文字的位置和样式，不另生成数字；角色和 policy 冲突时先修正规则，不删除批准正文。

### 字体路线

主控按项目气质选择中文字体，并把判断写进项目规则和 `deck_style.typography`。专业、医疗、宣教、商务、政府、课程培训等偏专业场景，中文主字体优先使用 `Microsoft YaHei`；偏可爱、儿童、轻松亲和、圆润插画风格，可以使用 `YouYuan` 或用户指定圆体。不使用 `PingFang SC` / 苹方作为执行字体或 fallback。代码只查禁用苹方这条红线，字体气质仍由主控结合风格图、试样图和用户反馈判断。

## 不适用与例外

本节写哪些页面不套普通内页标题或模块页规则，以及它们改用什么替代规则。至少覆盖：

- 封面：可探索构图，但继承项目风格，不强套普通页左上标题组件。
- 目录页：如存在，说明目录结构和是否使用独立标题。
- 结束页：保持整体风格，可按结束页角色处理，不强加普通内容页标题。
- 特殊大图页、证据页、练习页、视频截图页等：说明例外理由和仍需保持的公共元素。

例外必须有页码或角色范围、理由和替代模板。不能写“特殊情况灵活处理”后让每页临时发挥。

## 统一禁用项

本节写和一致性有关的禁止事项。常见禁用项包括：

- 禁止普通页标题一页左上、一页居中、一页变成徽章。
- 禁止模块页随机更换骨架、编号容器、主视觉槽位或背景语言。
- 禁止同一文字角色随机换字体、字号、颜色和字重。
- 禁止在用户未要求时添加可见页码、logo、水印或装饰文字。
- 禁止为了容纳长标题而单页删词、换词、缩到不可读。
- 禁止把页面规划索引页码、内部编号、来源说明或执行状态画进页面。
- 禁止让 `deck_style.json` 反向修改阶段1已确认的页面文字。

`图片风格.md` 的禁用项和本节禁用项由主控按本页风险归并进 `【关键约束】`；同义重复可以合并，否定含义不能删除。runtime 不把两份文档的全部禁用项自动追加到每一页。

## 最小自检

主控交给用户确认前，至少自查：

- 普通页标题规则是否具体到位置、容器、字体层级、装饰和长标题处理。
- 普通页是否默认只写页面标题组件；如出现章节标签/眉题，是否有明确启用条件、适用页、批准文字来源和角色绑定。
- 有模块页时，模块页模板是否写清固定骨架和允许变化。
- 无模块页时，是否明确写明不使用模块页模板。
- 公共元素是否说明出现条件，页码默认关闭是否清楚。
- 封面、结束页和特殊页是否有明确例外边界。
- 禁用项是否可执行，没有写成空泛口号。
- 规则是否能被主控整理成“PPT版式基因 + 本页布局”，而非强制逐条复制进每页提示词。
- 文档没有 `待主控大模型填写`、`TODO`、`TBD` 等占位内容。
