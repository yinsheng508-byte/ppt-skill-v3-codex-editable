# 核心不变量

本文件只定义所有具体 PPT 项目都必须遵守的跨阶段红线和权威分层；阶段细节、工具细节和特殊来源处理放在对应专题 reference。

## 规则权威层级

- `SKILL.md` 是短入口，只负责触发边界、恢复第一步、阶段骨架、reference 路由和停机条件。
- `references/` 是正式执行规则。当前阶段或当前专项被路由到的 reference，才是该动作的详细依据。
- `scripts/schemas/` 和 `scripts/runtime/` 是机器契约和被动执行器；它们不能替代主控判断，也不能自行推进阶段。
- `_state/project_state.json`、`_state/decisions/`、`_state/events.jsonl` 和用户明确确认，是具体项目的事实来源。
- `docs/current/` 与 `docs/archive/` 只是开发规划、任务卡、复盘或历史材料，不是具体 PPT 项目的正式执行规则。
- 根入口由当前主体决定：Codex 使用外层 `AGENTS.md`，WorkBuddy 使用外层 `CODEBUDDY.md`。二者都只负责把执行主体路由到 `.skill/SKILL.md` 和 `.skill/docs/维护说明.md`。
- 具体 PPT 项目仍以 `.skill/SKILL.md` 和被路由到的 `.skill/references/` 执行。

## 版本与兼容口径

- 稳定 Skill 调用名是 `ppt-skill-v3`，runtime package 是 `ppt_skill_v3`。
- 当前工作区、Skill frontmatter、agent metadata 和 runtime package 应保持同一 v3 正式标识。
- `legacy`、`v1`、`v2.3` 等历史口径只用于迁移、识别、warning 或历史契约说明；不能改变当前阶段流程。
- 详细维护规则见 `.skill/docs/维护说明.md`，普通项目流程不需要读取维护文档。

## 项目边界

- `.skill/` 是 Skill 根目录，外层目录是工作区壳层；二者都不是具体 PPT 项目目录，不得创建阶段0到阶段4产物。
- 具体 PPT 项目只能放在 `PPT输出/<中文项目名>/`。
- 阶段目录给用户和主控阅读，只放可读、可确认、可交付材料。
- JSON、packet、manifest、内部请求记录、日志、校验报告、worker 输出、中间 brief、素材索引、运行证据和主控决策全部放 `_state/`；其中主控决策统一放 `_state/decisions/`。
- 不直接修改源 PPTX，不直接把通用 PPT 编辑、外部导出稿或整理目录包装成阶段完成；除非用户明确要求跳过本 Skill 阶段流程或直接改文件。

## 主控与 runtime 边界

- 大模型是主控，负责资料取舍、叙事结构、审美判断、用户沟通、确认点和返工路由。
- Runtime 和脚本只做确定性动作：读取事实、生成草稿、补 envelope、校验路径与 hash、写事件与状态、拦截硬失败。
- 不允许 runner、文件存在、状态字段或脚本默认规则自行进入下一阶段。
- 阶段切换必须由主控显式记录 decision；decision 是放行记录，不是用户可见交付物。

## 阶段确认红线

- 阶段0只整理资料，不需要用户确认，也不生成正式页面规划。
- 阶段1固定确认四份真实材料：`页面规划.md`、`每页干净逐字稿.md`、`PPT一致性.md`、`图片风格.md`。
- 阶段2固定确认封面风格和图片版 PDF；试样确认只放行剩余页面，不替代图片版 PDF 确认。
- 阶段3基于用户确认的阶段2图片版 PDF 或用户确认外部锁定稿，输出演讲逐字稿、Word 和 PDF；K12 项目同时输出教案设计。
- Canva 等外部工具成果只可作为阶段3锁定稿来源，不自动算阶段3完成。
- 阶段3输出完成后必须写 `stage3_outputs_completed` 决策，才能进入阶段4整理。
- 阶段4只整理已存在交付物并派生 PDF 图片副本；整理器本身不生成新讲稿或教案，不自动完成项目。主控确认整理结果后写 `stage4_deliverables_organized`，项目才进入 completed。

## 内容与输出红线

- 阶段1内容资产是后续阶段的文字事实源。阶段2生图和阶段3逐字稿/教案都继承阶段1确认过的最终可见中文文字和页面任务。
- 阶段3可以自然扩写口播讲稿，但不能引入与 PPT 冲突的新事实，不能新增页面、重排页面或修改阶段1已确认内容。
- K12 教案可以把课件主线转成课堂任务链，但不得修改 PPT 页面、页数、页面结论或阶段1已确认内容。
- 阶段4只能复制、整理和从已存在 PDF 确定性派生 PNG，不得生成新逐字稿、教案、图片版 PPT 或其他阶段产物。

## 图片与证据红线

- 阶段2整页图片和阶段2封面候选只能走正式生图路线：默认 `openai_image_api`，或显式 `codex_image_gen`。
- 两条路线都必须保留 packet、batch manifest、对应路线 evidence、结果 ID、图片 sha、实际尺寸和必要的尺寸 warning。
- 不能用 fixture、本地渲染、source replay、HTML、canvas、SVG 或复制旧图冒充正式图片。
- 阶段2确认图必须使用一致且可追溯的 canonical 图片策略。

## 长任务防漂移红线

- 每次开始、恢复、用户确认、用户返工、上下文压缩、长任务继续、阶段切换和交付前，都先执行 `恢复与防漂移协议.md`，并优先使用 `resume-brief`、`next-action` 和 `drift-check` 控制面恢复事实、检查动作边界。
- 只相信当前项目事实来源，不用聊天记忆、文件存在或单次工具输出推断阶段完成。
- 单个长动作不得跨越用户确认点；长动作优先用 work packet 记录活动边界，到达确认点后停下来交给用户或写明缺口。
- 如果状态、决策、阶段目录和运行证据互相矛盾，先停下来汇报，不继续生成。

## 停止条件

出现以下情况时，先汇报当前阶段、缺口和下一步：

- 找不到具体项目目录或源文件。
- 当前目录是 Skill 根目录而非项目目录。
- 缺少进入下一阶段所需的用户确认或主控 decision。
- 缺少正式图片路线、生成 evidence、阶段3输出 manifest 或关键交付物。
- 用户要求阶段3逐字稿/教案，但没有已确认的阶段2图片版 PDF 或用户确认外部锁定稿。
- 工具不可用、浏览器不可控、第三方返回不完整，或 runtime/doctor 报出硬失败。
