# 阶段1设计合同规范

本文件规定阶段1 `design_contract.json`、页面规划和阶段1视觉资产如何形成。图片风格和 PPT 一致性的具体写法见对应专题 reference。

## 目标

阶段1除了用户可见的 `页面规划.md`、`每页干净逐字稿.md`、`PPT一致性.md` 和 `图片风格.md`，还必须由主控大模型写入机器态设计合同：

```text
_state/阶段1/design_contract.json
```

设计合同用于把路线、受众、资料边界、审美方向、页面角色和封面候选策略传递给阶段2。它不替代用户可见文档，也不由 runtime 自动生成正式内容。

## 与页面规划的关系

- `页面规划.md` 是阶段1权威逐页规划表。
- `每页干净逐字稿.md` 是阶段1用户阅读每页内容的干净审阅稿，必须从 `页面规划.md` 和 `content.json` 派生，不是另一套文字合同。
- `PPT一致性.md` 是阶段1用户可见的版式秩序文档，承载标题、模块页、页码、logo、公共元素、统一禁用项和例外边界。
- `图片风格.md` 是阶段1用户可见的画面气质文档，承载配色、质感、媒介、参考图解读、全局提示词方向和逐页图片规划。
- `content.json` 是 `页面规划.md` 的结构化镜像。
- `slide_prompt_briefs.json` 是阶段2 prompt brief。新请求的主控派生计划 `image_prompt_plan` 放在对应页中，正文仍从 `content.final_visible_text` 读取，不能在计划中另存正文。
- `design_contract.json` 是整套 PPT 的路线和视觉设计合同。

用户确认阶段1时，核心确认对象是：

```text
页面规划.md 的页数、页面角色、页面目的、每页最终可见中文文字、资料依据、内容保留边界
每页干净逐字稿.md 的逐页内容可读性和文字一致性
PPT一致性.md 的标题、模块页、公共元素、例外和禁用项
图片风格.md 的画面风格、参考依据和逐页图片规划
```

## 资料整合要求

阶段1写 `页面规划.md` 前，必须整合阶段0资产：

```text
阶段0_资料整理/资料清单.md
阶段0_资料整理/资料摘要.md
_state/阶段0/materials_index.json
_state/阶段0/原始资料/
_state/阶段0/提取文本/
```

如果用户提供 PPT、Word、PDF、截图、表格、讲稿和聊天口径，主控大模型必须判断主材料和补充材料，处理重复、冲突和缺口。整合结论必须落到 `页面规划.md` 每页的 `资料依据` 和 `内容保留边界`，不要另建单独用户可见资料整合文档。

## 页面规划文字合同

`页面规划.md` 建议表格：

```markdown
| 页码 | 页面角色 | 页面标题 | 页面目的 | 最终可见中文文字 | 资料依据 | 内容保留边界 | 视觉意图 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | cover | 高血压健康防护宣教 | 建立课程主题和行动承诺 | 高血压健康防护宣教；测得准 管得住 少并发；把血压管理变成每天做得到的小习惯 | 原PPT第1页 + 用户标题口径 | 不编造机构、讲者和来源 | 左侧标题层级，右侧护理测量场景 |
```

要求：

- “页码”是阶段规划索引，不代表阶段2/阶段3要在画面中添加可见页码；可见页码默认关闭，只有用户明确要求时才启用。
- “最终可见中文文字”必须逐条写清楚。
- “资料依据”必须能追溯到阶段0材料、原 PPT 页码、文档章节或用户口径。
- “内容保留边界”必须写清哪些文字、数字、术语、案例和结论不能删改。
- 仿做升级型默认 `preserve` 或 `soft_polish`，不能为了美观强压缩。

## 每页干净逐字稿

`阶段1_规划确认/每页干净逐字稿.md` 必须让用户能舒服地逐页审内容，不用在宽表格里读长文本。

基本要求：

- 每页使用 `## 第 01 页｜页面标题` 作为页标题。
- 每页保留简短的 `页面角色` 和 `本页目的`，帮助用户判断内容任务。
- `页面可见文字` 必须使用贴近页面结构的 Markdown 排版：封面用标题层级，目录用编号列表，知识讲解用小标题和要点，流程页用步骤，表格页用 Markdown 表格，总结页用编号结论。
- 不把多条文字用长分号挤在一行里。
- 不放资料依据、prompt、视觉说明、JSON 字段、内部制作说明或来源链接清单；这些仍放 `页面规划.md` 或 `_state/`。
- 不新增 `页面规划.md` / `content.json` 之外的页面可见文字；如为了排版补小标题，必须先同步写回 `页面规划.md` 和 `content.json`。
- 缺失信息在阶段1规划的资料说明中标记待补充，不自动写入页面可见文字；只有用户明确要在画面保留占位时，才把该占位作为批准正文。不得编造缺失信息。

## 图片风格

`阶段1_规划确认/图片风格.md` 必须合并原先风格方向和图片提示词概要，不再拆成两个用户可见文件。

建议结构：

- 整体风格与参考依据：用户原话、参考图、实际解读及借鉴范围。
- 当前生效风格与禁用项：配色、字体气质、质感、背景、留白、装饰和图像媒介。
- 不同页面的应用：封面、内容、章节、流程和图表页如何继承画面气质；标题、页码和模块骨架仍以 `PPT一致性.md` 为准。
- 逐页图片规划：按页说明构图、主视觉与必要例外。
- 调整记录：修改原因、影响页与保留图片依据，历史不混入当前规则。

要求：

- 保留会影响阶段2生成的风格、构图、文字密度、提示词和禁止项信息。
- 主控可以合并同义的颜色、字体、禁止项和风格描述，但不截取首句或按字数裁剪；具体色号、小数、数量与否定含义完整保留。
- 正式实际提示词只在阶段2 `图片生成提示词.md` 面向用户展示；packet、hash、provider JSON 和执行日志继续放内部目录。
- 不让 `图片风格.md` 修改 `页面规划.md` 已确认的每页文字。

共同风格以当前图片风格文档为准。deck或候选卡里相容的缺项须先补回当前风格或逐页规划；过期默认规则不进入请求。四封面在同一配色、媒介和字体范围内变化构图与视觉重点。

待生成页在现有brief中保存 `image_prompt_plan`；封面候选先写design_contract中的option brief，派发时同步style card，具体字段及登记命令见 [提示词建设规范.md](提示词建设规范.md)。标题、章节和安全区组件解析为plan.layout中的实际位置要求，不在最终编译时再次追加。`text_roles`只引用批准文字条目；页码仍依据已确认 `page_number_policy` 单独编译一次。该计划是主控归并后的派生结果，不新增第二份用户风格文档。

系统添加的生成指令只写横版画面，不填写输出像素、数字比例或清晰度等级；尺寸留接口参数。来源说明和阶段流程留规划或实际prompt代码块外，不能混入画面指令；正文中的数字、尺寸知识与专业术语不受此限制。

## 禁止事项

- 不把 `design_contract.json` 放入用户可见阶段目录。
- 不让 `每页干净逐字稿.md` 成为第二套事实来源或绕过 `页面规划.md` 修改内容。
- 不再新建独立的 `风格方向.md` 或 `图片提示词概要.md` 作为阶段1正式用户可见产物；历史项目如已有这两个文件，应合并为 `图片风格.md`。
- 不用设计合同改变用户已确认的每页内容。
- 不让 runtime 自动写正式设计判断。
- 不让阶段2 prompt 使用 `页面规划.md` 之外的新文字。
