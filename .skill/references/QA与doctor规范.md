# QA 与 doctor 规范

本文件只定义 QA、doctor、runtime、主控判断和用户确认的职责分层；详细质量清单见 `质量审查标准.md`。

## 分层

- Schema 校验：检查 JSON 结构、字段类型、必填字段和枚举值。
- Doctor：检查项目目录、状态、阶段资产、正式路线证据、stale/legacy 产物和硬失败。
- 阶段 QA：记录阶段2审美 QA、阶段3逐字稿生成检查、K12 教案设计检查、阶段4整理交付检查等专项结果。
- 质量画像：提供主控判断辅助，例如密集页、warning、推荐抽查页和 QA 覆盖缺口。
- 主控判断：审美、叙事、资料取舍、返工层级、风险接受和用户沟通。
- 用户确认：阶段1、阶段2封面风格、阶段2图片版 PDF 等固定确认点。阶段3逐字稿/教案和阶段4整理由主控检查与 decision 收口，不新增用户最终确认点。

## Doctor 职责

Doctor 是项目一致性和硬失败检查器，不是自动执行器，也不是审美裁判。

Doctor 应用于：

- 恢复已有项目时。
- 准备进入用户确认点前。
- 阶段2图片版 PDF、阶段3 DOCX/PDF 生成后，以及阶段4整理交付后。
- 状态、目录、决策或 evidence 之间出现不一致时。
- 长任务中断后需要判断能否续做时。

Doctor 发现硬问题时，不能继续推进阶段或交付；先修复记录、补证据、返工或汇报阻断。

阶段1/2图片流程中，Doctor 还应检查：阶段0没有提前生成图片风格文档；阶段1只有一个 `图片风格.md` 入口；阶段2的 `图片生成提示词.md` 链接可打开且不直接依赖 `_state`；试样 selection、正式结果、实际图片 sha、image_deck manifest 和当前风格依据一致。`img/` 中存在图片不代表已确认，只有当前 selection 或正式结果记录可作为试样展示和 PDF 输入依据。

新请求还须核对有效 `image_prompt_plan`、批准正文、规范版本、packet.prompt及冻结摘要的一致性；页型/文字角色冲突或来源过期时定位到具体页。指令区检查不能清洗正文，也不能凭关键词存在断言语义完整。旧成功或在途快照仍按原依据处理，不因表达版本升级自动失效；成功文档只能展示有图结果，代码块与当次实际prompt一致，来源说明置于块外。

Doctor读取阶段2实际图片，按 [生图证据链.md](生图证据链.md#尺寸和清晰度策略) 分别核对像素宽高和目标比例。目标16:9的默认相对比例容差为2%，包含边界；超出时记录warning，不因像素足够就视为横版通过。旧结果缺少比例字段时只读核算；记录宽高与实际文件不一致时单独报告，不改原图、历史证据或用户确认。比例偏差由主控明确返工或接纳，不当作自动审美结论。

## 阶段 QA 职责

- 阶段2审美 QA 关注视觉系统一致性、中文文字、页面角色、信息密度、伪字、页码和模块结构统一。
- 阶段3逐字稿 QA 关注页码绑定、内容一致、口播自然度、DOCX/PDF 可打开、中文字体、PDF 可选择、无截断重叠和 manifest 可追溯。
- 阶段4整理 QA 关注主题文件夹结构、已存在产物复制、PDF 图片派生、skipped 记录和不伪造缺失产物。
- K12 教案自审关注 K12 条件、阶段1和教材材料追溯、目标-活动-评价对应、课时安排、学科专项、安全提示、教学反思边界和教案 Word/PDF 表格质量。内容质量由主控模型判断，runtime 只保留可确定的底线检查。页数本身不进入硬失败，也不生成低页数提示；PDF 页数只作为排版结果记录，内容是否偏薄由主控按教师使用场景判断。

阶段 QA 记录是证据，不是阶段切换本身；阶段切换仍需主控 decision 和必要的用户确认。

阶段2审美 QA 的详细检查项、`review_scope`、返工路由和禁止事项统一维护在 `质量审查标准.md`。本文件只说明职责分层：runtime 可以生成草稿、校验结构、撤销受影响确认位和记录 evidence，但不让 runtime 自动判断审美，也不把试样确认当作最终图片版 PDF 确认。

阶段2可使用 `create-stage2-visual-qa-draft` 生成视觉 QA 草稿。草稿默认 `needs_rework`，只把 doctor、质量画像摘要和阶段2图片线索列出来；主控必须补充真实审美/视觉判断后，才能用 `record-stage2-visual-qa` 正式入账。

阶段2审美 QA 不能出现“整体通过但单页 finding 或检查项要求返工”的矛盾记录。需要返工时，runtime 只撤销受影响范围的阶段2确认位并回到主控处理；是否接受轻微审美风险仍由主控记录理由。

阶段3逐字稿和 K12 教案不使用独立坐标 QA 草稿。逐字稿由主控按 `阶段3逐字稿与教案输出规范.md` 检查，并通过 `speaker_script_manifest.json`、必要的 `_state/阶段3/` 辅助记录和阶段决策收口；K12 教案可使用 `record-lesson-plan-qa` 或写入 `_state/阶段3/lesson_plan_qa.json` 记录主控自审。

K12 教案自审写入 `_state/阶段3/lesson_plan_qa.json`，或体现在主控阶段决策中。该文件语义是“主控自审记录”，不是复杂评分表。阶段3完成前，必须已经生成教案 Markdown、DOCX、PDF 和 `lesson_plan_manifest.json`，且不存在硬问题。`pass_with_warnings` 可以完成阶段3，但 warning 和需教师课前调整的事项应留在 `_state/阶段3/lesson_plan_qa.json`、manifest 或阶段决策中；`fail` 或明确阻断项不能完成阶段3。

## 质量画像职责

质量画像只帮助主控发现风险，不直接判定通过或失败。

主控使用质量画像时，应判断：

- 推荐高风险页是否已覆盖。
- 未覆盖页是否有理由。
- warning 是否需要返工、接受或转入用户确认问题与反馈。
- 阶段3和阶段4的可读性、manifest、PDF 文本探测和整理派生风险是否需要返工或说明。

## 硬失败与主控判断

硬失败的详细清单以 `质量审查标准.md` 为准。一般包括缺用户确认、缺正式路线 evidence、目录污染、源图和 hash 不一致、交付物缺失、阶段4整理伪造缺失产物等。

K12 教案设计的硬失败还包括：K12 条件无法确认却强行生成完成、缺少足以判断 K12 的学段/学科/课题依据、缺阶段1内容资产或锁定稿来源、实验活动缺安全提示、教案 DOCX/PDF 缺失或不可打开、教师可见文档出现内部字段或未知占位。课时、教材版本、班级等无法确认时通常作为 warning 或教师课前调整项，不应在教师可见文档中硬写。教案页数多少都不单独构成硬失败，项目一致性检查不因页数目标替主控判定内容质量。

主控判断包括审美、表达、信息密度、页面是否太花或太空、复杂页是否需要拆分、讲稿是否自然和专业风险是否需要补充调研。

Runtime 可以拦截硬失败；不能替主控接受审美风险，也不能替用户确认。

## 执行建议

常用验证命令：

```bash
python3 .skill/scripts/pptctl.py doctor --run-dir <项目目录>
python3 .skill/scripts/pptctl.py validate-stage1 --run-dir <项目目录>
python3 .skill/scripts/pptctl.py validate-style-templates
PYTHONPATH=scripts/runtime python3 -m unittest discover -s tests
```

具体 PPT 项目验收时，优先顺序是：schema 或命令校验、doctor、阶段专项 QA、主控视觉/内容复核、用户确认。

## 与其他规则的关系

- `核心不变量.md` 定义不可违反的跨阶段红线。
- `恢复与防漂移协议.md` 定义什么时候检查、如何恢复、如何停下来。
- `质量审查标准.md` 定义详细检查项和阶段口径。
- 阶段2、阶段3、阶段4的专题 reference 定义各自 QA 产物如何生成和入账。

正式结果的依据过期一般是硬错误。仅在阶段2主控返工状态、最终PDF尚未确认，且最近已执行的返工decision明确覆盖该页时，doctor把这项差异标为待重生warning，允许修复动作继续；范围外过期、缺图与图片hash不符仍为硬错误。新图返回后须重新验收。
