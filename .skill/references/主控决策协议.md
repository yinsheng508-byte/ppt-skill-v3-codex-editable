# 主控决策协议

本文件只规定主控 decision 的类型、记录格式、写入时机、basis 和阶段切换边界；用户确认红线和主控/runtime 职责边界以 `核心不变量.md` 为准。

## 原则

阶段切换必须来自主控大模型的显式决策。不能因为文件存在、状态字段变化、脚本默认规则或 handoff 文件存在就自动进入下一阶段。

普通 decision 优先使用：

```bash
python3 .skill/scripts/pptctl.py make-decision --run-dir <项目目录> --type <decision_type> --notes <说明>
```

需要用户确认的 decision 必须显式传 `--user-confirmed`。`record-decision` 继续兼容主控手写完整 JSON 的特殊场景。

决策文件放在：

```text
PPT输出/<中文项目名>/_state/decisions/
```

## 决策类型

```text
stage1_ready_for_user_review
approve_stage1_start_stage2
request_stage1_revision
stage2_cover_options_ready_for_user_review
approve_stage2_cover_style_start_image_deck
request_stage2_cover_style_revision
stage2_trial_first5_ready_for_user_review
approve_stage2_trial_first5_continue_remaining
request_stage2_trial_first5_revision
stage2_ready_for_user_review
approve_stage2_start_stage3
request_stage2_revision
stage3_outputs_completed
request_stage3_lesson_plan_revision
stage4_deliverables_organized
request_stage4_organize_revision
```

旧项目历史 decision 只能作为恢复线索读取，不是新项目正式路线。新项目不要再写旧阶段3编辑重建或旧阶段4讲稿完成决策。

## 决策文件示例

```json
{
  "schema_version": "2.0",
  "decision_id": "0002_approve_stage1_start_stage2",
  "project_name": "示例项目",
  "run_dir": "PPT输出/示例项目",
  "decision_type": "approve_stage1_start_stage2",
  "from_stage": "stage1",
  "to_stage": "stage2",
  "actor": "main_controller",
  "user_confirmed": true,
  "controller_reviewed": true,
  "basis": {
    "confirmed_files": [
      "阶段1_规划确认/页面规划.md",
      "阶段1_规划确认/每页干净逐字稿.md",
      "阶段1_规划确认/PPT一致性.md",
      "阶段1_规划确认/图片风格.md"
    ],
    "image_generation_route": "openai_image_api",
    "notes": "用户确认页面规划、逐页干净正文、PPT一致性和图片风格，可以进入阶段2封面候选与后续图片版 PDF。"
  },
  "execution": {
    "allowed_actions": [
      "dispatch_stage2_cover_options",
      "run_image_api_batch",
      "record_image_result"
    ],
    "image_generation_route": "openai_image_api",
    "slide_indices": [1, 2, 3, 4, 5]
  },
  "created_at": "2026-08-02T00:00:00+08:00"
}
```

## 执行规则

- Runtime 只能执行 `execution.allowed_actions` 明确列出的动作。
- 阶段2生图路线不新增 decision 类型；在 `execution.image_generation_route` 或 `basis.image_generation_route` 中记录 `openai_image_api`（默认）或 `codex_image_gen`。没有显式记录时，主控默认按 `openai_image_api` 执行。
- `user_confirmed=false` 时不能执行用户确认后的阶段切换。
- `controller_reviewed=false` 时不能进入下一阶段。
- 返工 decision 只能把流程退回指定阶段，不能顺便自动重跑后续阶段。
- 决策文件是放行记录，不是用户可见交付物。
- `approve_stage1_start_stage2` 只打开阶段2A封面候选，不直接生成全套整页图片。
- `approve_stage2_cover_style_start_image_deck` 必须基于用户选择的封面风格，并要求 `deck_style.json` 和 `layout_intent.json` 已写入。
- `stage2_trial_first5_ready_for_user_review` 指阶段2B试样已准备好，让用户确认视觉、文字、密度和风格方向；命名沿用历史 first5，默认试样为5页总确认范围，包含已选封面。
- `approve_stage2_trial_first5_continue_remaining` 只表示试样方向通过，可以 promotion 已通过试样并继续生成剩余页面；不表示阶段2图片版 PDF 已确认。
- `request_stage2_trial_first5_revision` 表示试样需要返工，默认返工 `deck_style.json`、`layout_intent.json` 或阶段2 prompt，不修改阶段1内容资产。
- `stage2_ready_for_user_review` 指图片版 PDF 已准备好，不指封面候选已准备好。
- `approve_stage2_start_stage3` 指用户确认阶段2图片版 PDF 可作为阶段3锁定稿，主控可生成逐字稿、Word、PDF，并按需生成 K12 教案。
- `stage3_outputs_completed` 指阶段3逐字稿三件套已生成并由主控检查通过；K12 且 `stage3_outputs.lesson_plan.required=true` 时，同时表示教案三件套已生成且无硬问题。该决策进入阶段4整理，不代表项目已经完成。
- `request_stage3_lesson_plan_revision` 指阶段3 K12 教案被用户或主控打回重做；该决策只撤销教案确认位，不撤销已通过的逐字稿或阶段2锁定稿。
- `stage4_deliverables_organized` 指阶段4主题文件夹整理完成，复制和 PDF 图片派生结果已经由主控检查，项目进入 completed。该决策必须引用有效 `organize_summary` 或 `deliverable_manifest`；`organized_dir` 只能用于交叉核对，不能单独作为完成依据。
- `request_stage4_organize_revision` 指整理目录需要重新整理、补复制或清理历史残留；该决策不重新生成阶段3产物。

## 生图路线执行动作

阶段2可使用以下 route-aware 动作名。旧动作名只作为 runtime 兼容别名识别；新决策必须优先写这些当前动作名：

- `dispatch_stage2_cover_options`：派发阶段2A四封面候选 packet，默认 `openai_image_api`，可显式 `codex_image_gen`。
- `record_image_result`：主控把官方 `image_gen` 输出或中转 API 输出逐张登记成正式 result。
- `run_image_api_batch`：只用于 `openai_image_api` 中转路线。
- `dispatch_stage2_trial_first5`：派发阶段2B试样 packet。
- `dispatch_stage2_remaining`：派发阶段2B剩余页面 packet。

官方 `codex_image_gen` 路线不能写 `run_image_api_batch`；中转 API 路线不能缺少 `run_image_api_batch` 或等价 API 执行证据。

## 阶段2A封面风格决策边界

封面风格通过后，主控必须先判断选中封面候选能否直接作为正式封面页。只要没有明显质量问题，应先执行转正动作，再进入阶段2B试样派发。

```json
{
  "decision_type": "approve_stage2_cover_style_start_image_deck",
  "from_stage": "stage2",
  "to_stage": "stage2",
  "user_confirmed": true,
  "basis": {
    "confirmed_files": [
      "_state/阶段2/cover_options/selection/selection.json",
      "_state/阶段2/deck_style.json",
      "_state/阶段2/layout_intent.json"
    ],
    "notes": "用户选择封面风格，主控确认选中封面候选无明显质量问题，可直接转正为正式封面页。"
  },
  "execution": {
    "allowed_actions": [
      "promote_selected_cover_option",
      "dispatch_stage2_trial_first5",
      "run_image_api_batch"
    ],
    "image_generation_route": "openai_image_api"
  }
}
```

```json

  "decision_type": "approve_stage2_start_stage3",
  "from_stage": "stage2",
  "to_stage": "stage3",
  "user_confirmed": true,
  "controller_reviewed": true,
  "basis": {
    "confirmed_files": [
      "阶段2_图片版PPT/pdf/<封面第一页主题>｜图片版PPT.pdf"
    ],
    "locked_presentation_source": {
      "source_mode": "stage2_image_deck",
      "source_path": "阶段2_图片版PPT/pdf/<封面第一页主题>｜图片版PPT.pdf",
      "confirmation_basis": "用户确认阶段2图片版 PDF 作为阶段3逐字稿/教案输出锁定稿。"
    },
    "notes": "主控确认阶段1内容资产与阶段2图片版 PDF 足够支撑阶段3输出。"
  },
  "execution": {
    "allowed_actions": [
      "build_speaker_script"
    ]
  }

```

K12 项目进入阶段3时，主控或 decision helper 应根据 `education_context` 同步写入 `project_state.stage3_outputs.lesson_plan.required=true` 和 `required_reason`。`execution.allowed_actions` 可补充：

```json
[
  "build_lesson_plan_context",
  "build_lesson_plan"
]
```

## 阶段4整理决策边界

阶段4整理命令只复制和派生已存在文件，不写 decision。主控检查整理结果后记录完成决策：

```json
{
  "decision_type": "stage4_deliverables_organized",
  "from_stage": "stage4",
  "to_stage": "stage4",
  "user_confirmed": false,
  "controller_reviewed": true,
  "basis": {
    "confirmed_files": [
      "阶段4_文件整理交付/<主题名称>/每页干净逐字稿.md",
      "阶段4_文件整理交付/<主题名称>/<封面第一页主题>｜图片版PPT.pdf",
      "阶段4_文件整理交付/<主题名称>/<封面第一页主题>｜逐字稿.docx",
      "阶段4_文件整理交付/<主题名称>/<封面第一页主题>｜逐字稿.pdf"
    ],
    "organize_summary": "_state/阶段4/organize_summary.json",
    "notes": "主控确认阶段4整理目录符合交付规范，缺失项已按 skipped 记录，项目完成。"
  },
  "execution": {
    "allowed_actions": []
  }
}
```

K12 项目有教案 PDF 时，阶段4整理还应包含教案 DOCX/PDF 和 `教案设计图片/page_*.png`；逐字稿 PDF 存在时应包含 `逐字稿图片/page_*.png`。PNG 派生失败不阻断其他文件整理，但必须写入 skipped。

完成决策的 summary/manifest 必须包含 `schema_version`、`status`、`project_name`、`run_dir`、`topic`、`organized_dir`、`copied`、`rendered`、`skipped` 和 `created_at`。主控必须确认已确认阶段的核心交付物出现在 `copied` 中；如果这些核心产物在 `skipped` 中记录为 `source_missing`，不得写完成决策。`pdftoppm_missing` 和 `pdf_render_failed` 只影响 PDF 图片副本，已复制 DOCX/PDF 核心文件时可以作为 skipped 记录保留。

## 阶段2B试样决策边界

试样是阶段2B内部确认点，不新增正式大阶段。

试样通过：

```json
{
  "decision_type": "approve_stage2_trial_first5_continue_remaining",
  "from_stage": "stage2",
  "to_stage": "stage2",
  "user_confirmed": true,
  "basis": {
    "confirmed_files": [
      "阶段2_图片版PPT/img/slide_001.png",
      "阶段2_图片版PPT/img/slide_002.png"
    ],
    "notes": "用户确认当前 selection 记录对应的试样方向可继续，主控可复用试样并生成剩余页面。"
  },
  "execution": {
    "allowed_actions": [
      "promote_stage2_trial_first5",
      "dispatch_stage2_remaining",
      "run_image_api_batch"
    ],
    "image_generation_route": "openai_image_api"
  }
}
```

```json
{
  "decision_type": "request_stage2_trial_first5_revision",
  "from_stage": "stage2",
  "to_stage": "stage2",
  "user_confirmed": false,
  "basis": {
```
