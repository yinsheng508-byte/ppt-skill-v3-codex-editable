## 适用场景

用户在具体 PPT 项目的阶段0、恢复项目或补充资料时，提供以下任一材料，就按本规范处理：

- `https://mp.weixin.qq.com/`、`http://mp.weixin.qq.com/` 或微信内打开的公众号文章链接。
- 微信公众号文章截图、长图、PDF、HTML、复制全文。
- 用户说“这篇公众号文章作为资料”“参考这篇微信文章”“把这篇公众号内容做成 PPT”。
- 用户说“提取内容、做阶段0资料整理、做 PPT 内容完整提取、仿写”。
- 多篇公众号链接作为资料包、案例库或参考来源。

## 核心原则

微信公众号资料只走一条完整路径：先做成可追溯的阶段0资料包，再交给阶段1规划。不要按“普通文章 / PPT 截图 / 长图 / 混合文章”拆成多条执行路线；这些只作为资料形态标记，不能改变主流程。

阶段0目标是把公众号文章变成可追溯、可摘要、可复用的资料资产，不生成正式页面规划、最终可见文字或图片提示词。

主控大模型必须完成：

- 保留用户给出的原始链接、接收时间和用户口径。
- 获取或登记标题、公众号名称、作者、发布时间、正文、图片/图表、视频/音频和外链线索。
- 固定生成正文清洁稿、图片清单、联系表、OCR 原文、逐页/分段结构化提取、仿写素材提炼和阶段0摘要。
- 图片上的文字必须逐图完整提取：标题、小标题、正文、表格、脚注、图例、流程节点、数值、单位、角标、水印和结尾页文字都要进入 OCR 原文或低置信记录；不得只提炼大意，不得省略小字。
- 没有正文、没有图片、OCR 失败或链接不可访问时，也按同一路径写入空结果、失败原因和所需用户补充，不改走临时路线。
- 在 `materials_index.json` 中登记为 `material_kind=wechat_article`，并记录内容形态、采集状态、OCR 状态和质量备注。
- 在 `资料清单.md` 和 `资料摘要.md` 中写清文章可用性、缺口和后续阶段1可引用的位置。

历史项目中，最常见的公众号 PPT 仿写资料是“公众号正文很短，正文图片里嵌了一整套横版 PPT 截图”。因此统一路径里必须默认做图片普查、联系表和 OCR；如果图片不是主体，也只是在结果里标记“图片非主体”，不跳过主流程。

## 唯一完整路径

所有微信公众号资料按下面顺序执行：

```text
1. 识别与建项
2. 抓取 HTML / 接收替代资料
3. 提取元数据
4. 登记原始 URL 和用户口径
5. 提取并清洁 HTML 正文
6. 提取正文图片 URL，按原顺序下载可用图片
7. 统计图片尺寸、比例、顺序和可读性，生成图片 manifest
8. 生成 source_contact_sheet 联系表
9. 对所有候选内容图执行完整 OCR
10. 汇总 OCR 原文
11. 写逐页/分段完整文字提取和结构化提取
12. 写仿写素材提炼
13. 刷新 materials_index.json
14. 写用户可见 资料清单.md 和 资料摘要.md
15. 做阶段0质量检查，判断是否足够进入阶段1
```

### 1. 识别与建项

收到链接后，先判断是否是微信公众号资料：

- host 包含 `mp.weixin.qq.com`。
- path/query 是微信文章页、预览页、历史消息页或转发短链。
- 用户截图里出现 `mp.weixin.qq.com` 且明确表示这是一篇公众号文章。

当前目录是 Skill 根目录时，必须先创建或定位：

```text
outputs/projects/<中文项目名>/
```

不要把 Skill 根目录当项目目录，不要在阶段0生成正式规划。

### 2. 抓取 HTML / 接收替代资料

先做一次通用打开尝试即可；如果打不开，不要反复搜索同一链接，立即切本机抓取。

优先使用：

```text
curl -L --compressed <url>
```

如果 `python urllib/requests` 遇到 SSL 握手慢、连接抖动或微信 CDN 卡住，直接切 `curl` 分批下载。遇到验证码、登录、权限或风险提示时，停下来让用户处理；如果用户提供截图、PDF、HTML 或复制全文，就把它们作为同一路径的替代输入继续处理。

### 3. 提取元数据

从 HTML 或替代资料中提取：

- 标题：优先 `msg_title`、`og:title` 或页面标题。
- 公众号名称：优先 `profile_nickname`、`nickname`、作者区文本或 meta。
- 作者/署名：有则保留，没有不要编。
- 发布时间：优先微信页面脚本时间戳、正文时间、meta。
- 正文容器：优先 `#js_content`。
- 原始 URL：保留用户发来的链接；可另存去除明显跟踪参数的 `canonical_url`。

### 4. 登记原始 URL 和用户口径

先登记 URL 资料：

```text
type=url
material_kind=wechat_article
source=<用户原始链接>
label=<文章标题，未知时用 微信公众号文章 mat_xxxx>
role_hint=primary / supporting / inspiration / evidence
source_priority=high / medium / low
locator_hint=公众号文章；标题/账号/日期/关键段落待提取
```

用户常同时给出口径，例如：

- “需要做这份内容的仿写。”
- “不需要参考文献。”
- “最后一页放感谢聆听。”
- “主体内容不变，可以适当补充完善。”

这些要求必须写入 `资料清单.md` 的任务口径和 `materials_index.json` 的 `user_constraints`，并在结构化提取里标注参考文献页、二维码页、购买页、投稿页是否排除。

### 5. 提取并清洁 HTML 正文

提取文本固定保存为：

```text
_state/阶段0/提取文本/mat_0001_wechat_article.md
```

正文清洁规则：

- 保留标题、公众号名称、作者、发布时间、原始 URL 和采集方式。
- 保留正文层级、列表、表格、引用、图片占位和图表说明。
- 删除无关广告、关注引导、赞赏、评论区、阅读量、点赞提示、模板化免责声明。
- 对文章中的外链、小程序、视频、音频只记录线索，不把未打开内容当作已采集事实。
- 如果 HTML 正文很短，也要写明“正文短，主体疑似在图片/OCR结果中”，不要空着。

### 6. 提取并下载正文图片

按 DOM 顺序提取 `data-src`、`data-backsrc`、`src`，去重但保留原顺序。

下载时固定做三件事：

- 尝试保留可用的最高分辨率版本；微信图片可尝试原 URL 和明显的高分辨率变体，例如 `/0`。
- 记录每张图片的原始顺序、本地路径、宽高、比例、sha、下载状态和来源 URL。
- 将头像、二维码、赞赏码、投稿海报、尾部广告标记为 `non_content_image`，不要删除证据。

图片固定放：

```text
_state/阶段0/原始资料/wechat_images/
```

### 7. 图片普查与内容形态标记

图片下载后统一写 manifest，并做内容形态标记。这个标记只影响摘要描述和质量备注，不改变主流程。

建议字段：

```json
{
  "content_shape": "slide_sequence / article_text / long_image / mixed / media_only / unavailable",
  "html_text_chars": 860,
  "image_count": 57,
  "candidate_content_image_count": 56,
  "candidate_slide_image_count": 56,
  "long_image_count": 0,
  "non_content_image_count": 1,
  "main_material_observation": "正文说明较短，正文图片中连续 56 张为 1080x608 横版课件截图"
}
```

横版 PPT 截图识别口径：

- 16:9 近似比例：`width / height` 在 1.70 到 1.82 之间。
- 4:3 近似比例：`width / height` 在 1.28 到 1.40 之间。
- 宽度优先大于等于 800；如果只有 640 宽但确认为页序，也保留并标记低分辨率。

### 8. 生成联系表

无论图片多少，都生成或记录联系表结果：

```text
_state/阶段0/source_contact_sheet.jpg
```

如果没有可用图片，写入 `source_contact_sheet_status=no_images` 到 manifest。联系表用于快速确认：

- 页序是否连续。
- 是否混入广告/二维码/投稿页。
- 封面、目录、模块页、结尾页是否都在。
- 是否有参考文献页、购买页、二维码页需要按用户口径排除。

### 9. OCR

对所有候选内容图执行完整 OCR。没有候选内容图时，写入 `ocr_status=not_applicable_no_content_images`。

完整 OCR 要求：

- 每张候选内容图必须有对应 OCR 文件，即使识别为空也要写空结果和失败/低置信原因。
- OCR 原文先完整保留，再做结构化整理；不要用摘要、主题提炼或人工大意替代 OCR 原文。
- 标题、小标题、正文、表格、流程节点、图注、脚注、页眉页脚、单位、数值、英文缩写、二维码旁说明、水印和结束页文字都要尽力提取。
- 表格和流程图要保留行列/节点顺序；识别不稳时写“疑似/待核对”，不要直接删掉。
- 如果用户要求“不需要参考文献”或“最后一页感谢聆听”，原图中的参考文献页、二维码页仍要在 OCR 原文中记录；结构化提取和阶段1建议中再标记为排除或替换。

OCR 默认优先级：

1. macOS Vision OCR：优先用于中文截图、浅色背景、医学课件和小字号页面。
2. Tesseract `chi_sim`：用于补充、交叉验证或 Vision 不可用时降级。
3. 双路 OCR：医学阈值、表格、流程、评分表、小字号密集页建议 Vision + Tesseract 同时跑，整理时互相补漏。
4. 人工/主控复核：关键医学数值、单位、评分表、药名、缩写和标题错字必须抽样看原图。

Tesseract 常见参数：

```text
--psm 3
--psm 12
```

如果 Tesseract 在 `/tmp` 或长中文路径下读图失败，先把图片放在项目 `_state/阶段0/原始资料/` 下的短路径再跑；不要因为 OCR 工具问题误判图片不可读。

OCR 原文固定放：

```text
_state/阶段0/提取文本/ocr_raw/
_state/阶段0/提取文本/PPT逐页OCR原文汇总.md
```

`PPT逐页OCR原文汇总.md` 必须逐图列出，不得只列有内容的图片：

```markdown
## S01 | image_001.png | ocr_status=complete

原始 OCR：
...

低置信/待核对：
- ...
```

### 10. 逐页/分段结构化提取

统一输出：

```text
_state/阶段0/提取文本/主体内容逐页结构化提取.md
```

如果来源是连续 PPT 截图，按 `S01`、`S02` 这种源页 ID 写；如果来源是正文或长图，按 `A01`、`A02` 这种资料段 ID 写。源页 ID/段 ID 只代表阶段0来源定位，不是阶段1正式 PPT 页码。

结构化提取必须建立在完整 OCR 原文之上，不能因为阶段0摘要需要简洁就省略图片文字。建议同时保留两层：

- `完整文字提取`：尽量贴近图片文字，按标题、正文、表格、脚注、图注分块保留。
- `结构化内容`：对完整文字进行资料级转述，供阶段1理解和仿写。

每个条目建议包含：

```text
源ID | 来源位置 | 内容功能 | 完整文字提取 | 结构化内容 | 低置信/待核对 | 阶段1引用提示
```

结构化内容要做资料级转述，但不能删除完整文字提取层。若图片文字太多，完整文字提取放 `_state`，用户可见摘要只放结构化转述和指向路径。

### 11. 仿写素材提炼

统一输出：

```text
_state/阶段0/提取文本/仿写素材提炼.md
```

必须包含：

- 原稿叙事公式。
- 值得保留的骨架。
- 适合升级的地方。
- 可复用内容主题。
- 阶段1可选改写方向。
- 风险和缺口。
- 用户口径对后续页面的影响，例如不放参考文献、终页感谢聆听。

### 12. 写阶段0用户可见材料

`阶段0_资料整理/资料清单.md` 必须说明：

- 任务口径。
- 原始链接和公众号元数据。
- HTML、图片、联系表、OCR、结构化提取、仿写提炼的位置。
- 资料质量和缺口。

`阶段0_资料整理/资料摘要.md` 必须说明：

- 总体理解。
- 内容形态观察。
- 原稿结构。
- 逐页/分段内容提取。
- 图片文字完整提取状态，包括总图片数、候选内容图数、OCR 完成数、低置信页和未提取原因。
- 可用于仿写的核心内容。
- 阶段1注意事项。

摘要可以充分梳理，但不能出现正式新 PPT 页码、最终可见文字清单或阶段2 prompt。

## 归档结构

阶段0用户可见目录只放：

```text
阶段0_资料整理/资料清单.md
阶段0_资料整理/资料摘要.md
```

运行资料统一放：

```text
_state/阶段0/
  materials_index.json
  source_contact_sheet.jpg
  source_article_manifest.json
  downloaded_images_manifest.json
  ocr_run_manifest.json
  原始资料/
    wechat_article.html
    original_url.txt
    capture_notes.md
    wechat_images/
  提取文本/
    mat_0001_wechat_article.md
    ocr_raw/
    PPT逐页OCR原文汇总.md
    主体内容逐页结构化提取.md
    仿写素材提炼.md
  网页资料/
    微信公众号/
      mat_0001/
        metadata.json
        images_manifest.json
```

没有真实 HTML、截图或图片下载结果时，不创建空证据文件；在 `capture_notes.md`、manifest 或 `metadata.json` 记录未获取原因。

## materials_index 字段

`materials_index.json` 是阶段1引用资料的机器态入口。微信公众号文章记录建议包含以下字段；没有值的字段可以省略或置为 `null`：

```json
{
  "id": "mat_0001",
  "type": "url",
  "material_kind": "wechat_article",
  "label": "文章标题",
  "source": "用户原始链接",
  "original_url": "用户原始链接",
  "canonical_url": "去除非必要跟踪参数后的链接",
  "received_at": "用户提供资料的时间",
  "account_name": "公众号名称",
  "article_title": "文章标题",
  "author": "作者或署名",
  "published_at": "YYYY-MM-DD 或原文日期",
  "capture_method": "direct_fetch / browser / user_copy / screenshot_ocr / pdf_export",
  "capture_status": "complete / partial / failed",
  "content_shape": "slide_sequence / article_text / long_image / mixed / media_only / unavailable",
  "html_text_chars": 860,
  "image_count": 57,
  "candidate_content_image_count": 56,
  "candidate_slide_image_count": 56,
  "source_unit_count": 56,
  "ocr_engine": "vision / tesseract / vision+tesseract / none",
  "ocr_status": "complete / partial / failed / not_applicable_no_content_images",
  "ocr_coverage": {
    "candidate_content_image_count": 56,
    "ocr_completed_image_count": 56,
    "ocr_empty_image_count": 0,
    "low_confidence_image_ids": ["S12", "S24"]
  },
  "stored_path": "_state/阶段0/提取文本/mat_0001_wechat_article.md",
  "structured_extract_path": "_state/阶段0/提取文本/主体内容逐页结构化提取.md",
  "paraphrase_notes_path": "_state/阶段0/提取文本/仿写素材提炼.md",
  "web_archive_dir": "_state/阶段0/网页资料/微信公众号/mat_0001",
  "source_contact_sheet": "_state/阶段0/source_contact_sheet.jpg",
  "role_hint": "primary",
  "source_priority": "high",
  "locator_hint": "公众号：账号名；日期；标题；S01-S56 或 A01-A10",
  "user_constraints": ["仿写", "不需要参考文献", "最后一页感谢聆听"],
  "quality_notes": "正文完整，图片 3 张未下载，关键医学数值需阶段1复核"
}
```

若 runtime 的通用登记只写入基础字段，主控大模型可以在登记后补充这些扩展字段。扩展字段是为了追溯和阶段1引用，不要求所有脚本都强校验。

## 资料清单写法

`资料清单.md` 的公众号资料要让用户一眼知道资料包状态：

```text
| mat_0001 | url | 文章标题 | wechat_article | primary | high | 公众号：账号名；2026-08-09；已完成 HTML、图片、联系表、OCR、结构化提取 | _state/阶段0/提取文本/主体内容逐页结构化提取.md |
```

如果正文未完整获取，定位提示必须写清：

```text
公众号链接已登记；正文需用户复制全文或补充截图；当前资料包为 partial，不建议直接作为阶段1主资料。
```

## 资料摘要写法

`资料摘要.md` 的主控摘要区建议为每篇公众号文章写一个二级小节：

```markdown
## mat_0001｜文章标题

- 来源：公众号名称，发布时间，原始链接。
- 用户口径：仿写 / 不放参考文献 / 最后一页感谢聆听。
- 采集状态：complete / partial / failed；采集方式。
- 内容形态观察：slide_sequence / article_text / long_image / mixed / media_only / unavailable。
- 资料包状态：HTML、图片、联系表、OCR、结构化提取、仿写提炼分别是否完成。
- 一句话主旨：
- 可用于 PPT 的内容资产：
- 关键事实与数据：
- 可视化机会：
- 需要核查或补充：
- 阶段1引用建议：主资料 / 补充观点 / 案例素材 / 不建议引用。
```

## 多篇文章处理

用户一次给多篇公众号文章时，仍然每篇文章独立跑同一条完整路径：

- 每篇文章独立 material ID，不能把多篇文章合并成一个 `mat_0001`。
- 每篇文章都要有自己的 HTML、图片 manifest、联系表、OCR 状态、结构化提取和仿写提炼。
- 按原始链接、标题、公众号、发布时间去重；转发链接和规范链接指向同一文章时保留用户原始链接，并记录 `canonical_url`。
- 在 `资料摘要.md` 增加“跨文章综合”小节，梳理共识、冲突、重复、独有案例和资料缺口。
- 阶段1的 `source_basis` 必须能定位到具体文章 ID 和源页/段 ID，不要写“多篇公众号资料”这种笼统来源。

## 质量检查

进入阶段1前，主控至少检查：

- 标题、公众号名称、发布时间是否已提取；没有则说明原因。
- 原始 URL、用户口径、接收时间是否已入账。
- HTML 正文、图片 manifest、联系表、OCR 原文、结构化提取、仿写提炼是否都有完成或失败状态。
- 每张候选内容图是否都有 OCR 原文或明确失败原因；`candidate_content_image_count` 必须等于 `ocr_completed + ocr_failed + ocr_not_applicable`。
- 完整文字提取是否覆盖图片里的小字、表格、流程节点、图注、脚注、数值和单位；低置信内容是否标注待核对。
- 正文是否完整；是否有“展开全文”、分页、图片文字、视频、外链未采集。
- 摘要中的事实是否能回溯到文章段落、图片、OCR 文件或用户补充口径。
- 是否误把广告、评论、读者留言、推广活动写入核心资料。
- 是否存在医疗、法律、财务等需要权威核查的高风险内容。
- OCR 原文、结构化提取和用户可见摘要之间是否分层清楚；用户可见摘要不能伪装成正式阶段1页面规划。
- 是否已经在 `资料清单.md`、`资料摘要.md`、`materials_index.json` 三处同步状态。

## 失败降级

失败降级不改变路径，只改变状态记录：

- 链接过期：登记 URL，标记 `capture_status=failed`，请用户复制全文或导出 PDF。
- 需要微信登录或验证：暂停采集，让用户在浏览器完成验证后继续。
- 只有截图：标记 `capture_method=screenshot_ocr` 和 `capture_status=partial`，继续做 OCR、结构化提取和摘要。
- 图片文字看不清：记录图片存在和不可读，不猜测。
- OCR 只能读出大标题：必须尝试高分辨率图、放大、Vision/Tesseract 双路或分区识别；仍失败时逐图记录失败原因，不得把该图从完整提取中省略。
- Tesseract 路径/格式异常：先换项目内短路径、原图直读、`--psm 3/12` 或 Vision OCR，不要立刻放弃。
- Python 下载 SSL 慢或失败：切 `curl` 分批下载，并记录失败 URL。
- 文章含多个视频/音频：记录媒体标题和位置，不把未转写内容纳入摘要。
- 文章明显是转载：保留公众号来源，同时在摘要中标记“原始来源待核查”。

## 禁止事项

- 不要把微信公众号文章处理拆成多条互斥路线；统一走完整资料包路径。
- 不要把微信公众号文章摘要当作阶段1页面规划。
- 不要因拿到一篇完整文章就自动进入阶段1；仍需判断资料是否足够。
- 不要把无法访问的链接内容编造出来。
- 不要把 OCR 不确定文字、图片里的模糊数字、评论区观点当作事实。
- 不要省略图片里的小字、表格、脚注、图注、流程节点、数值和单位；无法确认时标注待核对，而不是删掉。
- 不要在用户可见 PPT 正文中大段照搬原文；阶段1应改写、提炼并保留来源依据。
- 不要把公众号原文、截图、HTML、图片 manifest 放进阶段0用户可见目录。
