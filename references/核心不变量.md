# 核心不变量

本文件是 PPT Skill 的跨阶段红线和权威分层。它只放所有具体 PPT 项目都必须遵守的规则；阶段细节、工具细节和特殊来源处理继续放在对应专题 reference。

## 规则权威层级

- `SKILL.md` 是短入口，只负责触发边界、恢复第一步、阶段骨架、reference 路由和停机条件。
- `references/` 是正式执行规则。当前阶段或当前专项被路由到的 reference，才是该动作的详细依据。
- `scripts/schemas/` 和 `scripts/runtime/` 是机器契约和被动执行器；它们不能替代主控判断，也不能自行推进阶段。
- `_state/project_state.json`、`_decisions/`、`_state/events.jsonl` 和用户明确确认，是具体项目的事实来源。
- `docs/current/` 与 `docs/archive/` 只是开发规划、任务卡、复盘或历史材料，不是具体 PPT 项目的正式执行规则。
- `AGENTS.md` 约束本 Skill 仓库的维护方式；具体 PPT 项目仍以 `SKILL.md` 和被路由到的 `references/` 执行。

## 版本与兼容口径

- 稳定 Skill 调用名继续是 `ppt-skill-v2`，runtime package 继续是 `ppt_skill_v2`。
- 当前工作区或文档中出现 `v3` 时，只表示 Codex 可编辑路线和防漂移控制面的架构迭代，不代表正式调用名、package、schema id 或项目状态字段已经迁移。
- `legacy`、`v1`、`v2.3` 等历史口径只用于迁移、识别、warning 或历史契约说明；不能改变当前阶段流程。
- 详细维护规则见 `版本与兼容说明.md`。

## 项目边界

- 当前 Skill 根目录不是具体 PPT 项目目录，不得在 Skill 根目录下创建阶段0到阶段4产物。
- 具体 PPT 项目只能放在 `outputs/projects/<中文项目名>/`。
- 阶段目录给用户和主控阅读，只放可读、可确认、可交付材料。
- JSON、packet、manifest、prompt 原稿、日志、校验报告、worker 输出、中间 brief、素材索引和运行证据全部放 `_state/` 或 `_decisions/`。
- 不直接修改源 PPTX，不直接把通用 PPT 编辑结果包装成阶段3；除非用户明确要求跳过本 Skill 阶段流程或直接改文件。

## 主控与 runtime 边界

- 大模型是主控，负责资料取舍、叙事结构、审美判断、用户沟通、确认点和返工路由。
- Runtime 和脚本只做确定性动作：读取事实、生成草稿、补 envelope、校验路径与 hash、写事件与状态、拦截硬失败。
- 不允许 runner、文件存在、状态字段或脚本默认规则自行进入下一阶段。
- 阶段切换必须由主控显式记录 decision；decision 是放行记录，不是用户可见交付物。

## 阶段确认红线

- 阶段0只整理资料，不需要用户确认，也不生成正式页面规划。
- 阶段1固定确认三份真实材料：`页面规划.md`、`每页干净逐字稿.md`、`风格与提示词方案.md`。
- 阶段2固定确认封面风格和图片版 PDF；试样确认只放行剩余页面，不替代图片版 PDF 确认。
- 阶段3是 Skill 内正式可编辑 PPT 路线，默认走 OfficeCLI；若执行阶段3，必须确认文字坐标复刻，再确认可编辑 PPT。
- Canva 等外部工具成果只可作为外部锁稿，不自动算阶段3完成。
- 用户明确跳过 Skill 阶段3或确认外部锁稿时，可以基于已确认锁定稿进入阶段4，但必须写 decision，不能伪造成阶段3完成。
- 阶段4生成演讲稿、Word 和 PDF，由主控检查通过后完成，不再设置用户最终确认点。

## 内容与可编辑重建红线

- 阶段1内容资产是后续阶段的文字事实源。阶段2生图和阶段3填字都继承阶段1确认过的最终可见中文文字。
- 阶段3允许从阶段2用户确认图恢复文字几何坐标，但禁止把 OCR 或图片识别结果当作正式文字内容来源。
- 阶段3正式路线是坐标复刻加 OfficeCLI 可编辑构建；旧 `visual_slot_map + text_fill_plan 3.0 + preflight-stage3-overlay` 不是正式路线。
- OfficeCLI 结果必须有 provider evidence、命令或 tool call 证据、coordinate execution report、render review 和坐标复刻 QA。

## 图片与证据红线

- 阶段2整页图片、阶段2封面候选和阶段3保真去字背景只能走正式生图路线：默认 `codex_image_gen`，或显式 `openai_image_api`。
- 两条路线都必须保留 packet、batch manifest、对应路线 evidence、结果 ID、图片 sha、实际尺寸和必要的尺寸 warning。
- 不能用 fixture、本地渲染、source replay、HTML、canvas、SVG 或复制旧图冒充正式图片。
- 阶段2确认图、阶段3无字背景和阶段3坐标计划必须使用一致且可追溯的 canonical 图片策略。

## 长任务防漂移红线

- 每次开始、恢复、用户确认、用户返工、上下文压缩、长任务继续、阶段切换和交付前，都先执行 `恢复与防漂移协议.md`，并优先使用 `resume-brief`、`next-action` 和 `drift-check` 控制面恢复事实、检查动作边界。
- 只相信当前项目事实来源，不用聊天记忆、文件存在或单次工具输出推断阶段完成。
- 单个长动作不得跨越用户确认点；长动作优先用 work packet 记录活动边界，到达确认点后停下来交给用户或写明缺口。
- 如果状态、决策、阶段目录和运行证据互相矛盾，先停下来汇报，不继续生成。

## 停止条件

出现以下情况时，先汇报当前阶段、缺口和下一步：

- 找不到具体项目目录或源文件。
- 当前目录是 Skill 根目录而非项目目录。
- 缺少进入下一阶段所需的用户确认或主控 decision。
- 缺少正式图片路线、生成 evidence、OfficeCLI evidence 或关键交付物。
- 用户要求阶段4，但没有已确认的阶段3可编辑 PPT、阶段2图片版 PDF 或外部锁定稿。
- 工具不可用、浏览器不可控、第三方返回不完整，或 runtime/doctor 报出硬失败。
