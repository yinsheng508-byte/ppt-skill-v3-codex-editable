# 项目目录规范

## 核心原则

每个 PPT 项目必须有清晰的中文阶段目录。阶段目录给用户和主控大模型看，运行过程文件集中放到 `_state/`，主控决策放到 `_decisions/`。

## 用户可见目录

- `阶段0_资料整理/`：只放资料清单和资料摘要。资料摘要可以包含主控大模型维护的初步资料理解和缺口，但不能包含正式页面规划。
- `阶段1_规划确认/`：只放真实规划类 Markdown，不再放空壳 `用户确认_阶段1.md`。`页面规划.md` 是权威逐页规划表；`每页干净逐字稿.md` 是用户阅读每页最终可见文字的干净审阅稿，必须与页面规划和结构化内容逐页一致；`风格与提示词方案.md` 合并承载阶段1风格方向和图片提示词概要。用户直接确认这三份材料。
- `阶段2_图片版PPT/封面风格候选/`：只放四张封面候选图和中文选择说明。
- `阶段2_图片版PPT/前5页试样/`：只放阶段2B内部试样图和试样说明，不放 packet、prompt 或 JSON；目录名沿用历史命名，默认试样为3页，最多5页，可追加关键复杂页。
- `阶段2_图片版PPT/img/`：只放阶段2全套正式页面图；选中且质量通过的封面候选转正后会复制为对应 `slide_XXX.png`，未选中的封面候选仍只能留在 `封面风格候选/`。
- `阶段2_图片版PPT/pdf/`：只放由阶段2正式页面图打包出的图片版 PDF，新生成文件命名为 `<封面第一页主题>｜图片版PPT.pdf`。
- `阶段2_图片版PPT/阶段2_确认说明.md`：可选薄索引，只在已有封面候选、阶段2试样或图片版 PDF 后生成；它不是阶段推进依据。
- `阶段3_可编辑PPT/img/`：只放阶段3保真去字背景图。
- `阶段3_可编辑PPT/ppt/`：只放可编辑 PPT，新生成文件命名为 `<封面第一页主题>｜可编辑PPT.pptx`。
- `阶段3_可编辑PPT/坐标复刻预览/`：放阶段3无字背景上的坐标框预览、contact sheet 和索引 Markdown，是用户确认文字坐标复刻的主要材料。
- `阶段3_可编辑PPT/阶段3_确认说明.md`：可选薄索引，只在已有坐标预览或可编辑 PPT 后生成；它不是阶段推进依据。
- `阶段4_演讲稿输出/`：只放演讲逐字稿 Markdown、Word、PDF 和讲稿生成说明，新生成文件命名为 `<封面第一页主题>｜逐字稿.md/docx/pdf`。

## 运行过程目录

以下内容全部放 `_state/`：

- JSON 状态文件。
- packet。
- manifest。
- prompt 原稿。
- 日志。
- 校验报告。
- worker 输出。
- 中间 brief。
- 素材索引。
- 提取文本。
- 原始资料归档。
- 网页资料归档，例如微信公众号文章的 URL、HTML/截图、图片清单、采集说明和 metadata。
- 微信公众号 PPT 截图型文章的联系表、原始图片序列、OCR 原文、逐页结构化提取和仿写素材提炼。
- 阶段1 `design_contract.json`、`content.json`、`slide_prompt_briefs.json`、`slides.json` 等主控资产。
- 封面候选 style card、packet、prompt、provider 结果、batch 记录和用户选择记录。
- 阶段2B试样 packet、prompt、provider 结果、batch、对应路线 evidence、试样 review 和 promotion 记录。
- 阶段2/阶段3 `codex_image_gen` 的 image_gen batch/call/output/run 记录，以及 `openai_image_api` 的并发 batch、api_call、api_output 和 api_batch_run 记录。
- 阶段2/阶段3图片的尺寸策略记录，包括 `target_size=2048x1152`、实际宽高、`meets_preferred_size`、`size_warnings` 和可能的降采样风险记录。
- 阶段2轻量审美 QA 记录。
- 阶段3 text ownership map、editable coordinate plan、OfficeCLI 坐标填字执行报告、OfficeCLI readback、render review、coordinate QA v2 和 editable deck manifest。
- 阶段外工具任务记录，例如 Canva 辅助编辑任务的 task、导入尝试、设计链接、逐页参考文案、页面审查、批量修改日志和人工待处理项。

主控决策 JSON 全部放 `_decisions/`。

## 阶段外工具任务目录

阶段外工具任务可以读取项目资产作为参考，但不属于阶段0到阶段4的正式流程，不改变 `project_state.current_stage`，不替代阶段确认或阶段交付。

Canva 辅助编辑任务记录建议放在：

```text
_state/工具任务/canva/<task_id>/
  task.json
  import_attempt.json
  design_link.json
  reference_text_by_slide.json
  page_audit.json
  batch_edit_log.jsonl
  manual_todos.md
```

这些记录只用于恢复和审计：

- 不放进 `阶段3_可编辑PPT/`。
- 不放进 `_state/阶段3/`。
- 不作为阶段3可编辑 PPT manifest。
- 不作为进入阶段4的默认锁定稿依据。
- 不反向覆盖阶段1逐字稿或阶段2确认图。

## 禁止事项

- 不要在阶段目录里放脚本中间文件。
- 不要把 Skill 根目录当作具体 PPT 项目目录。
- 不要把 `_state/project_state.json` 之外的文件当作机器事实源。
- 不要让阶段目录里的确认说明反向覆盖机器状态。
- 不要把封面候选图混进阶段2正式页面图的 `img/` 或阶段4讲稿输出目录。
- 不要把试样图直接混进阶段2正式 `img/`，除非用户已经确认试样并由 runtime 记录 promotion。
- 不要让阶段0资料摘要替代阶段1 `页面规划.md`。
