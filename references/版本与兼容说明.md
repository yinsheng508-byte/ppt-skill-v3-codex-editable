# 版本与兼容说明

本文件说明本 Skill 的命名、包名、历史字段和 legacy 口径。它只约束维护和恢复判断，不改变具体 PPT 项目的阶段流程。

## 稳定标识

- Skill frontmatter 的正式调用名继续是 `ppt-skill-v2`。
- 用户界面可以展示为 `PPT Skill v2（Codex 可编辑）`，默认提示词仍使用 `$ppt-skill-v2`。
- Runtime Python package 继续使用 `ppt_skill_v2`。
- Schema title、schema id、历史状态字段、项目恢复逻辑和本机密钥路径继续保留 `ppt-skill-v2` 或 `v2` 字样。
- 不因仓库目录、任务文档或架构改造计划中出现 `v3`，就迁移正式 Skill name、package name、schema id 或项目状态字段。

## 架构迭代名

- 当前工作区目录中的 `v3` 只表示 Codex 可编辑路线和防漂移控制面的架构迭代，不是新的正式 Skill 调用名。
- 文档中需要区分时，使用“稳定调用名 `ppt-skill-v2`”和“当前架构迭代 / Codex 可编辑工作区”。
- 版本无关的规则优先写“本 Skill”，避免把规则误绑定到某个目录名。

## 历史口径

- `v1` 只用于旧项目迁移、只读摘要或历史 runner 识别。
- `v2.3` 出现在部分 schema 或 reference 中时，是历史资产契约或规范演进标签，不代表独立流程。
- `legacy` 表示旧路线、旧状态或旧证据字段，仅用于识别、迁移、warning 或排雷。
- 阶段3正式路线始终以 `可编辑PPT路线.md` 为准：坐标复刻 + OfficeCLI 可编辑构建。旧 `visual_slot_map + text_fill_plan 3.0 + preflight-stage3-overlay` 不能作为新项目正式通过依据。

## 维护边界

- 普通架构改造不得顺手重命名 `ppt-skill-v2`、`ppt_skill_v2`、schema id、密钥目录或旧项目状态字段。
- 如未来要正式迁移到新 Skill name，必须单独立迁移任务，覆盖调用名、UI metadata、package imports、schema id、密钥路径、旧项目恢复、测试和发布兼容。
- README、AGENTS、agents metadata、SKILL frontmatter 和 runtime 注释应保持同一口径：稳定标识不变，当前仓库承载架构迭代。
