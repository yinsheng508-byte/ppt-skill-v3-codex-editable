# 视觉系统统一规范

## 目标

用户选择封面风格后，主控大模型要把这个方向沉淀成整套 PPT 的视觉系统，保证内页不是一页一个样。

这里要统一的是“项目内规则”，不是全局死模板。

视觉系统应继承阶段1 `design_contract.json` 和用户选中的封面 style card，再沉淀为阶段2正式执行资产：

```text
_state/阶段2/deck_style.json
```

## 必须统一的视觉家具

整套 PPT 中这些元素必须保持统一：

- logo 的位置、尺寸和留白规则。
- 左上角标题、章节标签或页面识别信息。
- 可见页码默认不显示；如用户明确要求加页码，再统一页码的位置和样式。
- 页眉、页脚、角标、分隔线等固定视觉家具。
- 字体体系和加粗规则。
- 标题区风格。
- 章节页或模块介绍页结构。
- 正文区域的大致布局逻辑。
- 强调色、辅助色和背景风格。

## 标题区和模块介绍页

内页顶部小标题是项目内强固定元素。用户没有特别要求时，普通内容页的小标题应使用同一位置、字号、颜色、字重、下划线/分隔线、图标或角标规则；每页只替换标题文字。不要让标题一页居中、一页偏右、一页变成圆角徽章、一页变成超大主标题。

模块介绍页、章节页和单元过渡页属于同一重复模板组。确定一种结构后，所有同类页面应保持同样的画面骨架和提示词结构，只替换：

- 模块编号。
- 模块标题。
- 必要的一行短说明或关键词。

应保持一致的元素包括编号容器、标题位置、分隔线、人物或主视觉位置、背景波形/留白、装饰图标和文字层级。不同模块介绍页不能随机改变编号形状、标题对齐、人物姿势、主视觉比例或背景节奏，除非用户明确要求每个模块做成差异化海报。

## 页码默认策略

画面可见页码默认关闭。主控大模型只有在用户明确要求“加页码 / 显示页码 / 保留页码”时，才启用 `deck_style.page_number_policy.enabled=true`，并写清页码位置、样式、适用页和豁免页。

不要把阶段1 `页面规划.md` 里的“页码”列理解成视觉页码。那一列只是规划索引和资料追溯用，不应进入阶段2图片 prompt 或阶段3可编辑文本对象。

## 字体路线

主控大模型需要先判断项目字体气质，再写入 `deck_style.typography` 和阶段3 `editable_coordinate_plan.text_units[].font`：

- 专业、医疗、宣教、商务、政府、课程培训等偏专业场景，中文主字体使用 `Microsoft YaHei`。
- 偏可爱、儿童、轻松亲和、圆润插画风格，中文主字体可以使用圆体，例如 `YouYuan` 或项目指定的圆体。
- 不使用 `PingFang SC` / 苹方作为执行字体或 fallback。
- 代码只做禁用苹方的红线检查，不自动判断页面该专业还是可爱；字体气质仍由主控看风格图和渲染图判断。

## 与设计合同的关系

- `design_contract.json` 写阶段1的审美意图和候选策略。
- `deck_style.json` 写用户选择封面后真正锁定的视觉系统。
- `deck_style.json` 可以比 `design_contract.json` 更具体，但不能违背已确认的内容改写边界。
- 如果阶段2试样暴露整体风格问题，优先修改 `deck_style.json` 的 style atoms、color contract、typography contract、image language 或 motif system。

## 大模型判断权

主控大模型可以根据项目决定：

- 是否显示 logo。
- 是否有用户明确要求显示页码；默认不显示。
- 内容页是重图、重表、重流程还是重观点。
- 标题区是强固定还是轻固定；如果用户指出顶部小标题漂移，必须改为强固定。
- 每页是否需要差异化构图。

但是一旦确定规则，整套 PPT 要遵守同一个项目内系统。

## 禁止事项

- 不让每页随机选择字体和标题位置。
- 不让普通内页顶部小标题的大小、位置、装饰和对齐方式随页漂移。
- 不让模块介绍页随机更换结构；同一套 PPT 中所有模块介绍页必须像同一母版，只替换模块文案。
- 不在用户未要求时添加可见页码。
- 如果用户要求页码，不让页码一页左、一页右、一页没有，除非有明确设计理由。
- 不让 logo 大小和位置随页漂移。
- 不把封面风格只停留在“好看”两个字，必须抽象成可执行规则。
- 不让 `deck_style.json` 反向修改阶段1已确认的页面文字。
