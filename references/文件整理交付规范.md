# 文件整理交付规范

本文件定义 `/文件整理` 与 `/整理` 快捷入口。它只整理当前项目中识别到且实际存在的对应产物，不等待用户确认，不生成新图片、PPT、讲稿或教案，不推进阶段，不写阶段确认 decision。

## 触发与恢复

用户输入 `/文件整理`、`/整理`，或明确要求把当前最终产出物整理成一个主题文件夹时，先执行 `恢复与防漂移协议.md`：

- 确认当前目录是具体项目目录，或先在 `outputs/projects/` 下定位具体项目。
- 读取 `_state/project_state.json`、最近 `_decisions/` 和当前阶段目录。
- `/整理` 是被动复制通道：状态、`user_artifacts`、`expected_user_paths`、标准路径和兼容旧路径都可以作为候选线索；候选文件实际存在就纳入，不需要等待用户确认。
- 当前项目仍在等待用户确认时，也可以整理已识别到的对应文件；但必须在回复中说明整理不代表用户已确认该阶段、不会改变 `confirmed`、`status` 或 `current_stage`。

## 输出位置

在当前项目目录根部创建或刷新一个主题文件夹：

```text
outputs/projects/<项目文件夹>/
  <主题名称>/
```

`<主题名称>` 优先取封面第一页主题，与阶段2、阶段3、阶段4正式交付文件名的主题来源一致；取不到时用项目名兜底。主题名称可以和项目文件夹名称重复。

不要新建 `最终交付/` 外层目录。

## 文件结构

整理后的目标结构为：

```text
<主题名称>/
  图片素材/
    slide_001.png
    slide_002.png
    ...
  每页干净逐字稿.md
  <主题名称>｜图片版PPT.pdf
  <主题名称>｜可编辑PPT.pptx
  <主题名称>｜逐字稿.docx
  <主题名称>｜逐字稿.pdf
  <主题名称>｜教案设计.docx
  <主题名称>｜教案设计.pdf
```

中间未识别到或实际不存在的文件直接跳过，不生成空文件、占位说明或交付清单。

## 纳入规则

- `图片素材/`：复制 `阶段2_图片版PPT/img/slide_*.png` 中的正式页面图片；不复制封面候选、前5页试样、联系表、QA 预览或 `_state` 中的图片。
- `每页干净逐字稿.md`：复制 `阶段1_规划确认/每页干净逐字稿.md`，保持这个固定文件名。
- `<主题名称>｜图片版PPT.pdf`：复制已存在的阶段2图片版 PDF，兼容旧路径 `阶段2_图片版PPT/pdf/图片版PPT.pdf`，目标文件名统一使用当前主题名称。
- `<主题名称>｜可编辑PPT.pptx`：识别到阶段3可编辑 PPT 且文件存在时复制；即使项目仍在等待确认，也不以 `confirmed.stage3_editable_deck=true` 作为复制门槛。复制不代表阶段3已确认。
- `<主题名称>｜逐字稿.docx` 与 `<主题名称>｜逐字稿.pdf`：复制阶段4讲稿 Word/PDF。Markdown 版讲稿是阶段4源稿，不放入整理文件夹。
- `<主题名称>｜教案设计.docx` 与 `<主题名称>｜教案设计.pdf`：识别到 K12 教案 Word/PDF 且文件存在时复制。Markdown 版教案和教案生成说明不放入整理文件夹。

## 覆盖与清理

- `/文件整理` 与 `/整理` 默认复制文件到主题文件夹，并覆盖同名目标文件。
- 如果主题文件夹已存在，不默认删除用户手动加入的其他文件。
- 对本次缺失的产物，不创建目标文件；如旧主题文件夹里已有同名旧副本，主控应提醒用户它可能是历史残留，只有用户明确要求清理时才删除。

## Runtime 建议

优先使用被动命令：

```bash
python3 scripts/pptctl.py organize-deliverables --run-dir <项目目录>
```

该命令只能读取项目状态、复制符合规则的已存在文件，并输出 JSON 摘要；不能生成新阶段产物、写 decision、修改 `project_state.current_stage` 或把文件存在当作阶段完成依据。
