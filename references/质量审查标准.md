# 质量审查标准

## 原则

质量审查分两层：

- 硬失败：真实性、确认点、目录边界、交付物存在、禁止 OCR 等红线问题。
- 主控判断：审美、信息密度、页面是否太花或太空、内页复杂度是否合适。

Runtime 只适合检查硬失败。主控大模型负责判断审美和返工路由。

阶段3 AI 质量画像属于主控判断辅助：它可以提示密集页、未解决 warning、OfficeCLI native style probe 建议、possible merged、OfficeCLI builder warning 和 QA 覆盖缺口，但不能单独把项目判为通过或失败。

## 硬失败

以下情况不能交付或进入下一确认点：

- 缺少用户对阶段1规划、阶段2封面风格或阶段2图片版 PDF 的确认；执行 Skill 内阶段3时缺少阶段3坐标或可编辑 PPT 确认。
- 正式图片不是来自选定的正式生图路线，或缺少 `codex_image_gen` / `openai_image_api` 对应 evidence。
- 同组多张图片没有按并发方式生成。
- fixture、本地渲染、source replay、HTML/canvas/SVG 冒充正式图片。
- 执行 Skill 内阶段3时，可编辑 PPTX 不存在，或只是整页图片冒充。
- OCR 字段或 OCR 推断结果被当成正式重建依据。
- 阶段2确认图和阶段3背景使用不同 canonical 尺寸策略但没有 postprocess/canonical evidence。
- 阶段2或阶段3正式图的实际尺寸、目标尺寸或 `size_warnings` 缺失，导致清晰度风险不可追溯。
- coordinate plan 的 path、sha、width/height 不对应同一个真实图片文件。
- 用户可见阶段目录混入 JSON、packet、日志、prompt 原稿等过程文件。
- 页数明显不一致或关键交付文件缺失。
- 阶段2B跳过试样直接生成全套正式图片，除非用户明确要求跳过。
- 试样未经用户确认就 promotion 到正式 `full_slide` results。

## 主控判断

主控大模型判断：

- 风格是否合适。
- 四张封面是否真的代表不同方向。
- 用户选中的封面风格是否被扩展到内页。
- logo、标题、页码、章节标签和文字布局是否项目内统一。
- 用户未明确要求时是否没有可见页码；用户要求时页码是否统一。
- 普通内页顶部小标题是否使用同一位置、字号、颜色、装饰和 prompt 片段。
- 多个模块介绍页是否使用同一结构和同一 prompt 片段，只替换模块编号、标题和短说明。
- 专业型内页是否讲清楚。
- 演讲型内页是否足够简洁。
- 页面是否太花、太空或太满。
- 试样是否已经暴露整体视觉系统、版式语法或提示词问题。

## 阶段1

检查：

- 页数是否明确。
- 每页是否有清楚的信息目的。
- 每页是否有核心内容和辅助内容。
- 页面顺序是否有叙事逻辑。
- `风格与提示词方案.md` 是否存在，是否同时覆盖风格方向和图片提示词概要。
- `风格与提示词方案.md` 是否足够指导阶段2封面候选和后续图片生成。
- 是否没有把阶段1风格和图片提示词概要拆成两个正式用户可见文件。
- 是否符合用户目标和受众。
- 是否说明后续会先生成四张封面风格候选。
- `页面规划.md` 是否逐页写清最终可见中文文字、资料依据和内容保留边界。
- `每页干净逐字稿.md` 是否存在，是否逐页排版清楚，是否方便连续审阅每页内容。
- `每页干净逐字稿.md` 是否与 `页面规划.md`、`content.json`、`slide_prompt_briefs.json` 的每页最终可见文字一致。
- `design_contract.json` 是否写清路线、受众、资料边界、内容改写边界和封面候选策略。

## 阶段2A

检查：

- 图片来自真实正式生图路线：默认 `codex_image_gen`，或显式 `openai_image_api` 中转 API。
- 图片优先目标尺寸为 `2048x1152`，实际尺寸、目标尺寸、偏好尺寸和 `meets_preferred_size` 已入账；低于 2K 的结果作为清晰度风险由主控判断。
- 四张封面风格明显不同。
- 四张封面是否基于 style card，有清晰差异、内页延展和风险说明。
- 用户可见目录只放封面图和选择说明。
- 用户选择后已写入 `deck_style.json` 和 `layout_intent.json`。

## 阶段2B

检查：

- 图片来自真实正式生图路线：默认 `codex_image_gen`，或显式 `openai_image_api` 中转 API。
- 正式页面图和试样都按 `2048x1152` 优先目标生成并保留尺寸记录；如低于 2K 或发生降采样，已作为清晰度风险记录。
- 是否先生成默认3页试样并让用户确认；必要时追加复杂页，总体保持轻量。
- 试样通过后是否保留证据并 promotion 到正式结果。
- 试样失败时是否默认返工阶段2设计规划和提示词，而不是修改阶段1内容资产。
- 全套图片使用用户选中的视觉系统。
- 用户未明确要求时没有可见页码。
- 普通内页顶部小标题没有漂移。
- 模块介绍页像同一母版重复使用，没有随机换结构。
- 中文文字可读。
- 不出现英文占位、乱码、假字。
- 主视觉和页面主题一致。
- 每页之间风格统一。
- 信息层级清楚。
- 图片不是纯装饰图。
- 如已记录 `_state/阶段2/visual_qa/stage2_aesthetic_review.json`，其中返工建议应指向正确范围。
- 图片版 PDF 可以打开。

阶段2轻量审美 QA 只抓明显问题：

- 视觉系统一致性。
- 文字可读性。
- 内容文字准确性。
- 页面角色匹配。
- 图片相关性。
- 无伪文字和占位符。
- 密度和层级。
- 页码默认关闭或按用户要求统一。
- 顶部小标题一致性。
- 模块介绍页一致性。

## 阶段3

检查：

- 可编辑 PPTX 存在且可以打开。
- 页数一致。
- 文字对象可编辑。
- 不把整页图片当最终可编辑 PPT。
- 不把多个独立文字区域合成一个大文本框。
- 不把多个 `text_unit` 合并成一个 PPT 文本框；execution report 必须能逐个反查每个 `text_unit_id` 的坐标、字号和颜色。
- 阶段3坐标确认前已生成坐标复刻预览和文字效果预演；预演只拦截明显字号、换行、底形和错位问题，不做多轮自动校准。
- 如 coordinate plan 使用 `display_text`、`wrap_policy` 或 `native_elements`，brief、plugin manifest 和 execution report 应能追溯这些字段。
- `_state/阶段3/ai_quality/stage3_quality_profile.json` 已生成或刷新；主控已查看 `recommended_high_risk_slides`、`native_style_probe_recommendation`、`risk_signals` 和 `qa_coverage_review`。
- 如存在 `controller_review_plan.draft.json`，最终 QA 已说明必看页是否覆盖；不采纳的推荐页写入 `accepted_quality_tradeoffs` 或 `recommended_high_risk_coverage.not_reviewed_with_reason`。
- 背景和阶段2视觉方向一致。
- 背景优先保留阶段2参考图尺寸策略和清晰度；如低于 2K、低于来源图或发生降采样，已作为清晰度风险记录。
- 中文文字排版可读。
- 用户未明确要求时没有新增可见页码；如用户要求页码，页码对象全套统一且可编辑。
- 不从图片 OCR 识别文字。

## 阶段4

检查：

- 阶段4锁定稿来源已由用户确认；来源可以是阶段3可编辑 PPT、跳过阶段3后的阶段2图片版 PDF，或用户确认的外部可编辑 PPT/PDF。
- `speaker_script.json` 全局只保留演讲标题和讲者身份，每页只保留页码、页面标题和逐字稿。
- 逐字稿不是页面文字照读版；每页内容自然、通顺、足够展开，且没有引入与 PPT 冲突的新事实。
- 如用户要求调研补充、页面内容明显偏薄，或主题属于高准确性场景，已按内容需要使用权威来源校准口径，并在 `_state/阶段4/` 或 `讲稿生成说明.md` 记录来源用途；不要为了完成流程堆来源。
- Word 版存在、可打开、使用结构化样式、第一页顶部题头、页眉页脚、中文字体与语言属性，以及每页讲稿区块；没有单独封面页。
- PDF 版存在、可打开、文字可选择，不是整页图片拼接，内容与 Word 来自同一份讲稿数据，并优先嵌入中文字体。
- Word/PDF 无明显截断、重叠、乱码、孤立标题或表格溢出。
- PDF 已抽查第一页、中间页和末页渲染图，确认第一页题头后直接进入第 01 页内容；DOCX 已用系统预览/Word/WPS 或 XML/文本抽取等方式确认中文内容未丢失。
- `讲稿生成说明.md` 写清生成路线、输出文件和检查结果。
- `_state/阶段4/speaker_script_manifest.json` 记录 DOCX/PDF 路径、sha、PDF 生成工具和检查状态。
- 如有返工，返工阶段和原因明确。
