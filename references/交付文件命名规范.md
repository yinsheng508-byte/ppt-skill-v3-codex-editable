# 交付文件命名规范

## 命名目标

阶段2、阶段3、阶段4的用户可交付文件必须能从文件名看出主题和类型，避免多个项目都叫 `图片版PPT.pdf`、`可编辑PPT.pptx` 或 `演讲逐字稿.docx`。

## 主题来源

交付文件名前缀取“封面第一页上的主题”。主控在阶段1必须把这个主题稳定写入：

- `_state/阶段1/content.json` 的 `deck_title`。
- 第 1 页或封面页的最终可见主标题，通常是 `slides[0].final_visible_text[0]`。
- `页面规划.md` 和 `每页干净逐字稿.md` 中第 1 页对应的封面主标题。

如果封面页的页面标题只是“封面”“首页”“标题页”等泛化名称，不得拿它当文件名前缀；应使用封面可见主标题或 `deck_title`。如果阶段1内容资产暂不可用，runtime 可以用项目名兜底，但主控交付前应按封面主题修正。

## 标准文件名

阶段2图片版 PDF：

```text
阶段2_图片版PPT/pdf/<封面第一页主题>｜图片版PPT.pdf
```

阶段3可编辑 PPT：

```text
阶段3_可编辑PPT/ppt/<封面第一页主题>｜可编辑PPT.pptx
```

阶段4逐字稿：

```text
阶段4_演讲稿输出/<封面第一页主题>｜逐字稿.md
阶段4_演讲稿输出/docx/<封面第一页主题>｜逐字稿.docx
阶段4_演讲稿输出/pdf/<封面第一页主题>｜逐字稿.pdf
```

阶段4 K12 教案设计：

```text
阶段4_演讲稿输出/教案设计/<封面第一页主题>｜教案设计.md
阶段4_演讲稿输出/教案设计/docx/<封面第一页主题>｜教案设计.docx
阶段4_演讲稿输出/教案设计/pdf/<封面第一页主题>｜教案设计.pdf
```

## 清理规则

文件名前缀要保留中文主题本身，但必须清理会破坏文件路径或造成歧义的字符：

- 把 `/ \ : * ? " < > |`、控制字符和换行替换为空格。
- 把全角分隔符 `｜` 从主题里移除，分隔符只由命名模板添加一次。
- 合并连续空格，去掉首尾空格、点号、下划线和横线。
- 主题过长时可以截短到可读范围，保留能识别项目主题的前半部分。

## 兼容旧项目

旧项目里已经存在的 `图片版PPT.pdf`、`可编辑PPT.pptx`、`演讲逐字稿.md`、`演讲逐字稿.docx`、`演讲逐字稿.pdf`、`教案设计.md`、`教案设计.docx`、`教案设计.pdf` 可以继续作为恢复和校验候选，不能因此判定项目损坏。

新生成、新入账和新交付一律使用主题化命名。manifest、`project_state.user_artifacts`、`project_state.expected_user_paths` 和主控决策中的 `confirmed_files` 必须记录真实路径，不要继续写旧固定名。
