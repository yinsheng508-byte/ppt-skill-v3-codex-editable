# 版式意图与可编辑重建规范

## 目标

记录整套 PPT 的版式意图，帮助阶段2图片生成和阶段3可编辑 PPT 重建保持统一。

不要把本规范理解成固定坐标系统。v2.3 不硬规定 `1600 x 900`，也不要求所有页面提前写死坐标。

## strict layout

只有当项目确实需要高精度可编辑还原时，主控大模型才选择 strict layout。

如果选择 strict layout，必须记录：

- 选择原因。
- 坐标或比例基准。
- 如何换算到 PPT。
- 哪些页面或元素需要严格定位。

不要把某个固定画布尺寸写成全局硬规范。

## 阶段2B试样

阶段2B先生成试样时，`layout_intent.json` 是最重要的返工对象之一：

- 如果试样整体风格方向对，但页面过满、过空、重复或层级不清，优先修订 `composition_grammar`、`slide_role_map` 和 `layout_slot_contracts`。
- 如果普通内页顶部小标题出现位置、字号、装饰或对齐漂移，优先修订 `global_layout.header_lock`、`layout_slot_contracts.shared_header` 和对应 final prompt 共享片段。
- 如果多个模块介绍页结构不一致，优先修订 `page_type_rules.section`、`layout_slot_contracts.section_intro` 和模块介绍页 final prompt 共享片段。
- 如果只是某几页中文文字不清或元素压住内容，优先修订对应页 final prompt。
- 不因为试样版式问题默认回到阶段1，除非用户明确要求修改内容、页数或页面任务。

## 阶段3可编辑重建

阶段3 brief 必须引用：

- `content.json`
- `deck_style.json`
- `layout_intent.json`
- 阶段2参考图
- 阶段3保真去字背景
- `_state/阶段3/text_ownership_map.json`
- `_state/阶段3/editable_coordinate_plan.json`

可编辑文字来自 `content.json`，不来自图片识别。

logo、标题、页码、章节标签、字体和正文布局遵守 `deck_style.json` 与 `layout_intent.json`。

可见页码默认不创建 slot、不生成文本对象。只有 `deck_style.page_number_policy.enabled=true` 且有用户明确要求时，阶段3才重建页码对象，并保证全套位置和样式统一。

普通内页顶部小标题和模块介绍页在阶段3必须延续阶段2已锁定的共享结构。允许从用户确认的阶段2图片恢复几何坐标，但不得借此重写标题层级、章节结构或文字内容。

阶段3必须先由主控大模型完成 `text_ownership_map.json`，再基于阶段2确认图精准识别/标注 `editable_coordinate_plan.json`，并交给用户确认；用户确认文字坐标复刻无误后，才能运行 OfficeCLI 坐标填字。`editable_coordinate_plan.json` 至少说明：

- 每页 `source_image`、宽高和 sha。
- 每个 `text_unit` 的 `ownership_id`、`content_source` 和准确文字。
- 每个 `text_unit` 的 `geometry_source`、`box_px` 和 `relative_box`。
- 字体 token、解析后的字体、字号范围、颜色 token 和解析后的颜色。
- 行距、文本框内边距、水平/垂直对齐。
- fit policy，默认不得自动缩字。
- 少量必要 `native_elements`。

这些内容是主控大模型的设计判断，不由本地脚本用默认值代替。

`text_unit` 的粒度必须等同于独立视觉文本对象。标题、副标题、编号、标签、每条 bullet、每张卡片标题/正文、流程节点编号/标题/说明、页码和注释等，只要位置、容器、字号、颜色、对齐或语义层级不同，就必须拆成独立 `text_unit`。OfficeCLI 坐标填字时一个 `text_unit` 对应一个 PPT 原生文本对象，不得合并。

## 禁止事项

- 不用 OCR 从图片识别文字内容。
- 不把 OCR、图片识别文字或 builder 猜测作为正式内容来源。
- 不用自动缩字把过多文字硬塞进一个框。
- 不跳过 `editable_coordinate_plan.json` 或用户坐标确认直接运行 OfficeCLI 坐标填字。
- 不把所有文字合成一个整页大文本框。
- 不把多个独立 `text_unit` 合成一个文本框。
- 不把整页图片冒充可编辑 PPT。
- 不让 `layout_intent.json` 自行删减 `页面规划.md` 中已确认的内容。
