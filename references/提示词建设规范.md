# 提示词建设规范

## 目标

阶段2图片生成前，主控大模型先写每页提示词草稿，再编译 final prompt。这样每页图片能追溯到内容、风格和版式意图。

阶段2 prompt 的内容来源必须是：

```text
页面规划.md 权威逐页规划表
-> 每页干净逐字稿.md 人类审阅稿
-> content.json
-> slide_prompt_briefs.json
-> design_contract.json
-> 风格与提示词方案.md
-> deck_style.json
-> layout_intent.json
-> final prompt
```

图片模型不能在 final prompt 之外自由新增页面文字。
`每页干净逐字稿.md` 只用于用户审阅和一致性校对，不允许成为绕过 `页面规划.md` / `content.json` 的新增文字来源。

## 两层提示词

第一层：`slide_prompt_briefs.json`

放在：

```text
_state/阶段1/slide_prompt_briefs.json
```

它记录每页要表达什么，不直接等同于正式生图 final prompt。

第二层：final prompt

放在：

```text
_state/阶段2/final_prompts/
```

它是交给当前选定正式生图路线的最终提示词；默认给 Codex 内置 `image_gen`，显式中转路线时给 `openai_image_api`。

## slide_prompt_briefs.json 建议字段

每页建议包含：

- `slide_index`
- `page_role`
- `message_goal`
- `final_visible_text`
- `visual_composition`
- `layout_family`
- `density_budget`
- `visual_anchor`
- `content_fidelity_policy`
- `main_visual_elements`
- `style_constraints`
- `negative_constraints`
- `acceptance_criteria`

## final prompt 必须包含

- 页面目的。
- 最终可见中文文字。
- 页面角色和版式家族。
- 信息密度预算。
- 视觉锚点。
- 主视觉元素。
- 构图和信息层级。
- 从 `design_contract.json` 继承的路线、受众、内容改写边界和通用审美意图。
- 从 `deck_style.json` 继承的视觉系统。
- 从 `layout_intent.json` 继承的版式意图。
- 普通内页必须继承同一顶部小标题 prompt 片段，只替换本页标题文字。
- 模块介绍页必须继承同一模块介绍页 prompt 片段，只替换模块编号、模块标题和必要短说明。
- 页码默认不显示；只有用户明确要求加页码时，final prompt 才能包含可见页码规则。
- 禁止项。
- 验收标准。
- 输出尺寸和清晰度：正式图优先目标为 16:9 `2048x1152`，高清锐利，尽量避免低分辨率、压缩感、马赛克、模糊边缘或小图放大感。

## 中文文字规则

正式图片里可见文字必须是中文。

提示词必须明确：

```text
不得改写、删减、增加、翻译或替换数字、单位、年份和专业术语。
不得新增装饰性伪文字。
用户未明确要求加页码时，不得在画面中出现可见页码。
不得出现英文占位词、拼音、乱码、假字或 lorem ipsum。
```

## 统一 prompt 片段

阶段2全套图片生成前，主控大模型应从 `deck_style.json.header_policy` 和 `layout_intent.global_layout.header` 编译一个普通内页顶部小标题 prompt 片段。除封面、目录、模块介绍页、结束页等明确豁免页面外，每页 final prompt 都复用这段文字，只替换本页标题：

```text
顶部标题区固定：在同一位置放置本页小标题“{slide_title}”，使用同一字体、字号、颜色、字重、对齐方式和分隔线/装饰；主体内容不得压住标题区；不要改变标题位置、大小或装饰风格。
```

如果 PPT 有多个模块介绍页或章节页，主控大模型还应编译一个模块介绍页 prompt 片段。所有 `section_divider` 页复用同一结构，只替换变量：

```text
模块介绍页固定结构：使用同一背景、编号容器、标题位置、分隔线、主视觉位置和装饰节奏；模块编号为“{module_index}”，模块标题为“{module_title}”，短说明为“{module_subtitle}”；不要随机改变编号形状、标题对齐、人物位置或背景波形。
```

这些片段可以直接写入每页 final prompt；如需单独追溯，可放在 `_state/阶段2/final_prompts/_shared_blocks.md`。不要把共享 prompt 片段放进用户可见阶段目录。

## 封面候选 prompt

四张封面候选的 final prompt 必须基于 `design_contract.json` 和对应 style card，且四张候选必须有明显差异。

差异可以来自：

- 构图。
- 主视觉。
- 质感。
- 色彩。
- 光影。
- 情绪。
- 信息密度。

不要只换颜色，也不要只替换同义词。

## 全套图片 prompt

全套图片生成时，主控大模型根据 PPT 类型判断内页复杂度：

- 专业型内容可以更丰富。
- 演讲型内容应更简洁。
- 方案型内容要兼顾信息密度和高级感。
- 资料改造型内容优先保留事实和原逻辑。
- 护理宣教型内容要专业可信、温和、可执行。
- 学术答辩型内容要保留论证链和证据锚点。
- 创赛路演型内容要有说服力但不能夸大事实。
- 仿做升级型内容基本不变，只升级页面设计和表达清晰度。
- 默认不加可见页码；不要把阶段1规划索引或原材料页码画进页面。
- 普通内页顶部小标题必须使用同一提示词片段，避免标题区漂移。
- 多个模块介绍页必须使用同一提示词片段和同一版式骨架，避免章节页互相不像一套。

## 阶段2B试样 prompt

阶段2B先生成试样时，trial prompt 仍是正式质量的 prompt：

- 必须使用当前选定正式生图路线，默认 `codex_image_gen`。
- 必须明确 16:9、2K、`2048x1152` 和高清锐利要求；试样也不能按低清草稿处理。
- 必须保留完整证据链。
- 必须包含每页 `final_visible_text`。
- 必须继承 `deck_style.json` 和 `layout_intent.json`。
- 如果试样失败，默认修改阶段2设计规划或 prompt，不修改阶段1内容资产。

runtime 只负责记录 prompt、hash、packet 和 provider 证据，不负责审美判断。
