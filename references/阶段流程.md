# 阶段流程

本文件定义阶段内容、阶段产物和进入条件；跨阶段红线以 `核心不变量.md` 为准，恢复和防漂移动作以 `恢复与防漂移协议.md` 为准。

## 总流程

```text
阶段0_资料整理
-> 阶段1_规划确认
-> 阶段2_图片版PPT
-> 阶段3_可编辑PPT（默认，可显式跳过或外部完成）
-> 阶段4_演讲稿输出
```

阶段规范是软导航，不是代码硬门禁。大模型负责判断是否继续、返工、暂停或完成。阶段2内部拆成封面风格候选、试样、剩余整页图片生成和图片版 PDF 打包几个动作。阶段3是默认可编辑 PPT 路线；用户明确选择跳过 Skill 阶段3，或使用外部工具完成可编辑化并确认锁定稿时，主控可以基于已确认锁定稿进入阶段4，但必须记录对应主控决策，不能把跳过或外部产物伪造成 Skill 阶段3完成。

## 阶段0：资料整理

目标：整理输入，不做正式规划。

主控大模型：

- 理解用户目标。
- 选择项目名。
- 整理资料清单和资料摘要，资料可以包括 PPT/PPTX、Word/DOCX、PDF、截图、表格、讲稿、文本和用户聊天口径。
- 资料包含微信公众号文章链接、`mp.weixin.qq.com` URL、公众号截图、PDF 或复制全文时，统一按 `阶段0微信公众号资料处理规范.md` 生成完整资料包：抓取或接收替代资料、提取元数据、清洁正文、下载图片并写 manifest、生成联系表、OCR、结构化提取、仿写素材提炼，再登记为 `material_kind=wechat_article` 并写清采集状态和缺口；图片文字必须逐图完整提取，不得用摘要代替 OCR 原文或跳过小字、表格、图注和流程节点。
- 判断资料是否足够进入阶段1。

阶段0产物是阶段1的输入：

- `阶段0_资料整理/资料清单.md`
- `阶段0_资料整理/资料摘要.md`
- `_state/阶段0/materials_index.json`
- `_state/阶段0/原始资料/`
- `_state/阶段0/提取文本/`
- `_state/阶段0/网页资料/`（可选；用于公众号文章、网页快照、图片清单和采集说明）

阶段0到阶段1的接力：

- `资料清单.md` 解决“有哪些资料”和“资料位置”的问题。
- `资料摘要.md` 解决“资料大致内容、可用性和缺口”的问题。
- `materials_index.json` 是机器态资料索引，阶段1每页 `source_basis` 应能追溯到这里的资料 ID、文件名、原 PPT 页码或文本段落。
- 微信公众号文章的 `source_basis` 应追溯到 `material_id`、文章标题、公众号名称、发布时间和正文段落/小节；不要只写“公众号文章”。
- 如果用户在阶段1过程中补充新资料，主控应先登记回阶段0索引并刷新阶段0可见文档，再继续阶段1规划。这是阶段0资料刷新，不是自动回退阶段。

禁止：

- 不生成正式页面规划。
- 不生成正式页数和逐页标题。
- 不生成每页最终可见文字。
- 不生成正式图片提示词。
- 不开始生图。

## 阶段1：规划确认

目标：由主控大模型基于阶段0资料和用户目标写规划，让用户确认。阶段1最重要的是把每页最终可见文字定死，后续阶段2生图和阶段3可编辑填字都继承同一份逐字稿。

阶段1必须先整合所有资料，再写 `页面规划.md`。不能按单一文件机械拼页；如果同时有 PPT、Word、PDF、截图和用户补充口径，主控大模型要判断主材料、补充材料、冲突处理和内容取舍。

产物：

- `阶段1_规划确认/页面规划.md`
- `阶段1_规划确认/每页干净逐字稿.md`
- `阶段1_规划确认/风格与提示词方案.md`
- `_state/阶段1/design_contract.json`
- `_state/阶段1/layout_safety_contract.json`
- `_state/阶段1/content.json`
- `_state/阶段1/slide_prompt_briefs.json`

`页面规划.md` 是阶段1权威逐页规划表，必须包含：

- 页码，作为规划索引使用，不代表画面上要显示可见页码。
- 页面角色。
- 页面标题。
- 页面目的。
- 最终可见中文文字。
- 资料依据。
- 内容保留边界。
- 视觉意图。

`每页干净逐字稿.md` 是阶段1给用户审阅内容的逐页阅读稿。它必须逐页呈现最终可见中文文字，使用 Markdown 标题、要点、编号、表格、流程等格式排版，避免把所有内容挤在表格单元格里。它不是新的内容来源，不能新增 `页面规划.md` 和 `content.json` 之外的页面文字；如发现不一致，先修正阶段1全部相关资产，再给用户确认。

`风格与提示词方案.md` 是阶段1唯一用户可见的风格和提示词方案文档。它合并原先 `风格方向.md` 和 `图片提示词概要.md` 的内容，必须同时写清初步风格方向、视觉系统、版式规则、全局提示词方向、统一 prompt 约束和逐页提示词概要；重复表述可以精简，但不能删掉会影响阶段2生成的风格或提示词信息。

`design_contract.json` 记录路线、受众、资料边界、内容改写边界、审美方向、页面角色和阶段2封面候选策略。它放 `_state/`，不放用户可见阶段目录。

`layout_safety_contract.json` 是轻量安全区合同。它只说明标题区、正文区、图像区、禁压区、文字归属策略和密度判断，不写最终逐行像素坐标，不做复杂模板引擎。

进入阶段2条件：

- 主控大模型检查规划完整。
- `页面规划.md`、`每页干净逐字稿.md`、`content.json`、`slide_prompt_briefs.json` 的每页可见文字一致。
- `风格与提示词方案.md` 已覆盖风格方向和图片提示词概要。
- `design_contract.json` 已写入并通过结构检查。
- `layout_safety_contract.json` 已写入；普通页允许粗区域，只有明显过密页面才返工拆页或压缩内容。
- 用户确认阶段1三份真实材料：`页面规划.md`、`每页干净逐字稿.md`、`风格与提示词方案.md`。不再使用空壳 `用户确认_阶段1.md` 作为确认材料。
- 写入 `approve_stage1_start_stage2` 主控决策。

## 阶段2A：封面风格候选

目标：基于阶段1 `design_contract.json` 生成四张不同风格的封面图，让用户选择整套 PPT 的视觉方向。

生成要求：四张封面默认先走 `codex_image_gen` 官方路线；用户明确指定、官方路线不可用或主控判断需要时，可走 `openai_image_api` 中转 API 路线。两条路线都必须记录 batch、对应路线 evidence、结果 ID 和图片 sha。优先目标尺寸为 16:9 `2048x1152`，尽量保留生成原始 raster，不主动降采样或压缩；若官方路线返回低于 2K，记录尺寸 warning，主控按实际清晰度决定继续、重试或切换路线。中转 API 路线默认模型 `gpt-image-2-vip`、尺寸 `2048x1152`、质量 `high`，单个 batch/run 最多 6 并发、单次最多等待 500s；官方路线由主控按 packet 调用内置 `image_gen` 工具并逐张入账。

主控大模型应先从 `design_contract.json` 生成四张候选 style card：

```text
_state/阶段2/cover_options/style_cards/cover_option_A.json
_state/阶段2/cover_options/style_cards/cover_option_B.json
_state/阶段2/cover_options/style_cards/cover_option_C.json
_state/阶段2/cover_options/style_cards/cover_option_D.json
```

style card 说明候选定位、构图、视觉媒介、色彩策略、字体方向、适合页面角色、内页延展和风险。用户不直接看 style card，只看封面图和中文选择说明。

产物：

- `阶段2_图片版PPT/封面风格候选/cover_option_A.png`
- `阶段2_图片版PPT/封面风格候选/cover_option_B.png`
- `阶段2_图片版PPT/封面风格候选/cover_option_C.png`
- `阶段2_图片版PPT/封面风格候选/cover_option_D.png`
- `阶段2_图片版PPT/封面风格候选/封面风格选择说明.md`
- `_state/阶段2/cover_options/style_cards/`

用户选择后，主控大模型写入：

- `_state/阶段2/cover_options/selection/selection.json`
- `_state/阶段2/deck_style.json`
- `_state/阶段2/layout_intent.json`

如果用户选中的封面候选本身没有明显质量问题（中文文字正确、无乱码/伪字、与阶段1封面文字一致、证据链完整、canonical 策略可追溯），主控应把该候选直接转正为阶段2正式封面页：

- 正式图片复制到 `阶段2_图片版PPT/img/slide_XXX.png`
- 正式结果写入 `_state/阶段2/results/slide_XXX.json`
- 正式结果 `purpose=full_slide`，保留原 `cover_option` 的生图路线 evidence、图片 sha、batch 路径，并记录 `promoted_from_cover_option=true`

只有当选中候选“风格可用但封面画面本身不可直接使用”时，才明确返工阶段2A封面或重做封面；不要为了进入阶段2B默认再生成一次封面。

进入阶段2B条件：

- 用户确认封面风格。
- 主控大模型检查并写入视觉系统和版式意图。
- 写入 `approve_stage2_cover_style_start_image_deck` 主控决策。

## 阶段2B：试样、整页图片与图片版 PDF

目标：按阶段1逐字稿生成带中文文字的整页图片，并打包为图片版 PDF。阶段2生成的是用户确认的视觉母版，阶段3会基于这套确认图恢复坐标；已由阶段2A转正的封面页直接属于这套正式图。

生成要求：阶段2B图片默认先走 `codex_image_gen` 官方路线；用户明确指定、官方路线不可用或主控判断需要时，可走 `openai_image_api` 中转 API 路线。两条路线都必须按 `execution_group` 建 batch manifest，并记录对应路线 evidence、结果 ID、实际尺寸和图片 sha。优先目标尺寸为 16:9 `2048x1152`，默认尽量不压缩、不降采样、不把原图另存为更小尺寸；低于 2K 的结果可以继续，应作为清晰度风险入账并由主控判断是否需要重试。中转 API 路线单个 batch/run 最多 6 并发、单次最多等待 500s；官方路线由主控按 packet 调用内置 `image_gen` 工具并逐张入账。

阶段2 prompt 必须继承：

- 阶段1逐字稿，只能使用 `content.json` 和 `slide_prompt_briefs.json` 中确认过的最终可见文字。
- `layout_safety_contract.json` 的文字区、图像区和禁压区。
- 已锁定的 `deck_style.json` 和 `layout_intent.json`。

阶段2允许牺牲一小部分自由绘画，换取阶段3更容易复刻。页面信息文字不要嵌入复杂图像内部，人物、设备、插画和装饰不要压住文字区。

内部流程：

```text
先把可用的已选封面候选转正为正式封面页
-> 生成尚未覆盖的阶段2B试样
-> 用户确认视觉、文字、密度和风格方向
-> 试样通过后生成剩余页面
-> 全套正式页面图齐全后打包图片版 PDF
```

试样：

- 默认取第1-3页作为试样确认范围；总页数不足3则覆盖全部页。已转正的封面页只列入试样说明和正式结果，不重复生图，所以实际新生成试样页数可以少于确认范围页数。
- 最多生成5页默认样本；如果默认样本不能代表全稿，主控可以额外加入关键复杂页，并记录原因。
- 试样图片仍必须来自选定正式生图路线，并保留完整证据链。
- 试样用户可见目录沿用：`阶段2_图片版PPT/前5页试样/`。
- 试样运行目录：`_state/阶段2/trial_first5/`。
- 试样确认不是阶段2最终确认，不替代图片版 PDF 确认。
- 试样失败时默认返工阶段2设计规划和提示词，不修改阶段1内容资产；只有用户明确要求改内容、页数或页面任务时，才回到阶段1。

产物：

- `阶段2_图片版PPT/前5页试样/`
- `阶段2_图片版PPT/img/`
- `阶段2_图片版PPT/pdf/图片版PPT.pdf`
- 可选薄索引：`阶段2_图片版PPT/阶段2_确认说明.md`，仅在已有封面候选、阶段2试样或图片版 PDF 时生成，不作为阶段推进依据。
- `_state/阶段2/visual_qa/stage2_aesthetic_review.json`

进入阶段3条件：

- 主控大模型检查图片质量，并可记录阶段2轻量审美 QA。
- 用户确认图片版 PDF。
- 写入 `approve_stage2_start_stage3` 主控决策。

## 阶段3：可编辑 PPT

目标：基于阶段2确认图生成保真去字背景和可编辑 PPT。

生成要求：阶段3保真去字背景默认先走 `codex_image_gen` 官方 edit 路线；用户明确指定、官方路线不可用或主控判断需要时，可走 `openai_image_api` edits/urls 中转路线。两条路线都必须以阶段2确认图作为 reference/edit 输入，按 `execution_group` 建 batch manifest，并记录对应路线 evidence、结果 ID、实际尺寸、图片 sha、阶段2来源图证据和 `restore_targets_hash`。阶段3优先保留阶段2参考图的原始清晰度和画布策略，尽量避免把背景缩小、压缩或重生为 1K 模糊图；若输出低于 2K 或低于阶段2来源图尺寸，记录尺寸 warning，主控按视觉效果决定继续、重试或换路线。正式背景路线必须是 `stage2_preserve_text_removed_background`，不能默认重生同风格背景。

阶段3内部固定按坐标复刻拆成七步，但目标是一次生成可编辑初稿，不默认做多轮自动校准：

1. 文字归属账本：主控大模型写 `_state/阶段3/text_ownership_map.json`，明确哪些文字去字后恢复为可编辑对象，哪些文字保留在背景。
2. 保真去字背景：以阶段2每页图片作为 reference/edit 输入，只移除 ownership map 派生的 `remove_and_restore` 目标，保留构图、插画、图标、卡片、光影和复杂视觉。
3. 坐标精准识别：必须基于阶段2用户确认过的每页图片识别/标注文字几何坐标；坐标只作为 geometry evidence，不能把 OCR 或图片识别文字当作内容来源。
4. 坐标复刻规划：主控大模型写 `_state/阶段3/editable_coordinate_plan.json`，每个 `text_unit` 绑定 `ownership_id`、准确文字、几何来源、像素框、相对框、字体、段落和溢出策略。
5. 坐标用户确认：主控把阶段3文字坐标复刻结果交给用户确认；用户确认无误并记录 `approve_stage3_coordinate_plan_start_text_fill` 决策前，不得运行 `build-editable-brief`，不得运行 OfficeCLI builder 填字。
6. OfficeCLI 坐标填字：OfficeCLI builder 基于无字背景和已确认 coordinate plan 生成可编辑 PPTX，同时输出 OfficeCLI readback、render review、PPTX/OOXML 反查 coordinate execution report 和 provider evidence。
7. 入账与坐标 QA：运行 `record-editable-deck` 入账正式 manifest，再由主控记录 `_state/阶段3/render_review/stage3_visual_qa_review.json`；execution report 覆盖全部文字单元，视觉 QA 只要求 contact sheet 加抽样页/高风险页记录；高风险页可补 `native_render_check.json`，但不把细微漂移做成慢门禁。

阶段3输入应包含：

- `_state/阶段1/content.json`
- `_state/阶段2/deck_style.json`
- `_state/阶段2/layout_intent.json`
- 阶段2图片版 PDF 或每页参考图。
- 阶段3保真去字背景图。
- `_state/阶段3/text_ownership_map.json`
- `_state/阶段3/editable_coordinate_plan.json`
- 用户对阶段3文字坐标复刻的确认决策。

产物：

- `阶段3_可编辑PPT/img/`
- `阶段3_可编辑PPT/ppt/可编辑PPT.pptx`
- `阶段3_可编辑PPT/坐标复刻预览/`
- 可选薄索引：`阶段3_可编辑PPT/阶段3_确认说明.md`，仅在已有坐标预览或可编辑 PPT 时生成，不作为阶段推进依据。
- `_state/阶段3/text_ownership_map.json`
- `_state/阶段3/editable_coordinate_plan.json`
- `_state/阶段3/text_fill_execution_report.json`
- 可选：`_state/阶段3/render_review/native_render_check.json`
- `_state/阶段3/render_review/stage3_visual_qa_review.json`

默认进入阶段4条件：

- 主控大模型检查可编辑 PPT，并记录通过的坐标复刻 QA v2。
- doctor 无阶段3 stale issue，execution report 覆盖全部 coordinate text units。
- 明显漏字、错字、数值单位错误、遮挡、溢出必须处理；细微字距、框宽、行高和局部对齐允许交付后人工后调。
- 用户确认可编辑 PPT。
- 写入 `approve_stage3_start_script_output` 主控决策。

跳过 Skill 阶段3进入阶段4条件：

- 阶段2图片版 PDF 已准备好并处于用户确认点。
- 用户明确确认阶段2图片版 PDF 可作为阶段4锁定稿，或明确要求跳过 Skill 阶段3直接生成演讲稿。
- 主控检查阶段1内容资产、阶段2锁定稿和页码映射足够支撑讲稿输出。
- 写入 `approve_stage2_skip_stage3_start_script_output` 主控决策；该决策只表示跳过 Skill 阶段3进入讲稿输出，不能设置 `stage3_editable_deck=true`，也不能冒充可编辑 PPT 已完成。

## 阶段4：演讲稿输出

目标：基于已经确认的锁定稿生成 PPT 演讲逐字稿，并输出 Word 版和同源 PDF。锁定稿可以是阶段3可编辑 PPT、用户明确跳过阶段3后的阶段2图片版 PDF，或用户确认的外部可编辑 PPT。

阶段4不做交付确认。主控完成质量检查后记录 `stage4_script_completed` 决策，项目进入 completed。

输入：

- `阶段1_规划确认/页面规划.md`
- `阶段1_规划确认/每页干净逐字稿.md`
- `_state/阶段1/content.json`
- 阶段4锁定稿来源，三选一：
  - `stage3_editable_deck`：`阶段3_可编辑PPT/ppt/可编辑PPT.pptx`、`_state/阶段3/manifests/editable_deck.json`、`_state/阶段3/render_review/stage3_visual_qa_review.json`
  - `stage2_image_deck`：`阶段2_图片版PPT/pdf/图片版PPT.pdf`
  - `external_editable_deck`：用户确认的外部 PPTX 或 PDF，并在决策 `basis` 和 `speaker_script.basis.locked_presentation_source` 记录路径、sha 和确认说明

阶段4内部流程：

```text
主控撰写 speaker_script.json
-> 生成用户可读 演讲逐字稿.md
-> 生成专业排版 Word
-> 生成同源 PDF
-> 检查 DOCX/PDF 可打开、页数和文本可读
-> 记录 stage4_script_completed 决策
```

产物：

- `阶段4_演讲稿输出/演讲逐字稿.md`
- `阶段4_演讲稿输出/docx/演讲逐字稿.docx`
- `阶段4_演讲稿输出/pdf/演讲逐字稿.pdf`
- `阶段4_演讲稿输出/讲稿生成说明.md`
- `_state/阶段4/speaker_script.json`
- `_state/阶段4/speaker_script_manifest.json`
- `_state/阶段4/speaker_script_qa.json`

讲稿要求：

- 每页必须绑定 PPT 页码、页面标题和逐字稿正文。
- 逐字稿要适合真实口播，不只是照读页面文字；每页可以自然展开得更详实，但不要写成机械说明书或资料堆砌。
- 主控先整体理解受众、场景、内容深浅和专业风险，再判断是否需要调研补充；用户要求调研补充、页面内容明显偏薄，或主题属于医学、护理、法律、财务、政策等高准确性场景时，可用权威来源校准口径和补足背景，并把来源用途记录到 `_state/阶段4/`，不要把来源字段塞进每页结构。
- 讲稿不能引入和 PPT 冲突的新事实。
- Word 使用结构化样式、第一页顶部题头、页眉页脚、中文字体与语言属性，以及每页讲稿区块；不要设置单独封面页。
- PDF 与 Word 使用同一份讲稿数据，文字可选择，优先嵌入中文字体，不用图片拼接冒充。

用户提出修改时，由主控大模型判断返工到阶段4、阶段3、阶段2或阶段1。
