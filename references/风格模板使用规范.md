# 风格模板使用规范

## 目标

风格模板用于帮助主控大模型在阶段1提出初步风格方向、阶段2生成四张封面候选、用户选择后沉淀 `deck_style.json` 和 `layout_intent.json`。

风格模板不是正式项目产物，也不是自动套用的死模板。每个具体 PPT 项目仍然必须根据主题、受众、资料密度和用户反馈做判断。

## 存放位置

风格模板放在：

```text
assets/templates/风格模板/
```

每个模板建议使用一个中文 Markdown 文件，例如：

```text
assets/templates/风格模板/医学PPT.md
```

模板注册表放在：

```text
assets/templates/风格模板/registry.json
```

新增模板时，先复制 `assets/templates/风格模板/模板骨架.md`，再把正式模板文件注册到 `registry.json`。

## 使用时机

- 用户输入风格模板快捷指令时，先从 `registry.json` 解析对应模板。例如 `/医学PPT` 对应 `assets/templates/风格模板/医学PPT.md`。
- 用户明确指定某类风格模板时，主控大模型读取对应模板。
- 阶段1写 `风格与提示词方案.md` 时，可以引用模板里的定位、色彩、字体、版式原则和 prompt 约束短句。
- 阶段2A生成四张封面候选时，可以把模板拆成四个明显不同但同属一个领域气质的候选方向。
- 用户选择封面后，主控大模型只能把被确认方向沉淀进 `_state/阶段2/deck_style.json` 和 `_state/阶段2/layout_intent.json`。

## 使用边界

- 快捷指令只调用风格模板，不代表用户已确认阶段1规划、封面风格、图片版 PDF 或可编辑 PPT。
- 不能跳过阶段2A四封面候选，除非用户明确要求主控直接代选。
- 不能因为模板存在，就让 runtime 自动选择风格或推进阶段。
- 不能把模板 Markdown 复制进阶段目录冒充正式规划。
- 不能把模板里的示例文字当成真实医学事实或真实报告数据。
- 不能让模板压过用户的最新要求；用户口径优先于模板默认值。

## 注册表字段

每个模板记录至少包含：

- `id`：机器可读英文 ID，只用小写字母、数字和连字符。
- `name`：中文名称。
- `status`：`active`、`draft` 或 `deprecated`。
- `template_path`：模板 Markdown 相对路径，必须位于 `assets/templates/风格模板/`。
- `triggers`：快捷指令列表，例如 `["/医学PPT"]`。
- `description`：一句话说明模板用途。
- `usage_policy`：必须声明是否遵守阶段流程、是否跳过用户确认、是否默认页码。

`usage_policy.skip_user_confirmations` 必须为 `false`。风格模板不能越过 PPT Skill v2 的用户确认点。
`usage_policy.page_number_default` 必须为 `false`。所有风格模板默认不加可见页码，只有用户明确要求时才启用。

## 维护流程

新增一个风格模板时：

1. 复制 `assets/templates/风格模板/模板骨架.md`，命名为新的中文模板文件。
2. 写清模板定位、用户口径、色彩、字体、固定视觉家具、常见页面版式、封面候选建议和质量检查。
3. 在 `assets/templates/风格模板/registry.json` 增加一条记录，设置 `id`、`triggers` 和 `template_path`。
4. 运行 `python3 scripts/pptctl.py validate-style-templates`。
5. 运行 Skill 校验：`python3 /Users/yinxinhe/.codex/skills/.system/skill-creator/scripts/quick_validate.py .`。

查看和解析模板：

```bash
python3 scripts/pptctl.py list-style-templates
python3 scripts/pptctl.py resolve-style-template --query /医学PPT
python3 scripts/pptctl.py validate-style-templates
```

## 模板应包含

- 适用场景和受众。
- 视觉关键词和禁用风格。
- 色彩、字体、页眉、页码、logo 和标题区规则。
- 页码规则必须写明默认不显示，除非用户明确要求加页码。
- 目录页、数据页、机制讲解页、流程页、表格页、总结页等常见页面建议。
- 图片和插画规则，尤其是插画式背景是否允许文字、如何避免密集小字和生成乱码。
- 内容密度、留白、信息层级原则，以及哪些页面需要文字增强、哪些页面应保持简洁；不可过度精简的知识点、事实、流程、数字或专业解释。
- 阶段2封面候选的差异化建议。
- `deck_style.json` 和 `layout_intent.json` 的可参考片段。

## 质量要求

风格模板必须能指导主控大模型做出稳定、可复用、可追溯的审美判断，但不能替代主控判断。

模板内容应避免空泛词，例如只写“高级”“好看”“科技感”。每条风格要求都应尽量落到颜色、位置、字号、留白、构图、图表、插画、信息密度或禁用项。
