# 封面风格候选规范

## 目标

阶段2正式生成全套整页图片并打包图片版 PDF 前，先基于阶段1 `design_contract.json` 生成四张不同风格的封面图，让用户选择整套 PPT 的视觉方向。

这是固定流程。除非用户明确说“你直接替我选”，否则主控大模型不能跳过用户选择，也不能让 runtime 自动选择。

## 触发时机

进入阶段2后先做阶段2A：

```text
阶段2A_封面风格候选
-> 用户选择风格
-> 锁定 deck_style 和 layout_intent
-> 选中且质量通过的封面候选直接转正为正式封面页
-> 阶段2B_全套整页图片与图片版 PDF
```

阶段2A 仍属于阶段2，不新增用户阶段目录。

## style card

四张封面候选在生成前，主控大模型必须为每个候选写 style card：

```text
_state/阶段2/cover_options/style_cards/cover_option_A.json
_state/阶段2/cover_options/style_cards/cover_option_B.json
_state/阶段2/cover_options/style_cards/cover_option_C.json
_state/阶段2/cover_options/style_cards/cover_option_D.json
```

建议结构：

```json
{
  "schema_version": "1.0",
  "option_id": "A",
  "basis_design_contract": "_state/阶段1/design_contract.json",
  "style_positioning": "",
  "best_for": [],
  "composition": "",
  "visual_medium": "",
  "palette_strategy": "",
  "typography_direction": "",
  "layout_extension": {
    "cover_to_inner_pages": "",
    "suitable_page_roles": [],
    "risky_page_roles": []
  },
  "risk_notes": [],
  "prompt_constraints": [],
  "selection_explanation": ""
}
```

style card 放 `_state/`，不放用户可见目录。用户只看封面图片和中文选择说明。

## 四张封面要求

四张封面必须：

- 默认由 Codex 内置 `image_gen` 官方路线生成；用户明确指定、官方路线不可用或主控判断需要时，可改走 `openai_image_api` 中转 API 路线。两条路线都必须按同一个 `execution_group` 建 batch manifest，并记录对应 evidence、结果 ID 和图片 sha。
- 优先目标尺寸为 16:9 `2048x1152`；尽量保留生成返回的原始 raster，不主动把封面候选压缩、降采样或另存为更小图。
- 使用同一个 PPT 主题和标题语义。
- 都是完整中文封面图。
- 风格明显不同，不只是换颜色。
- 都能扩展成整套 PPT 的视觉系统。
- 不出现英文占位、乱码、假字、伪文字。
- 每张封面必须绑定对应 style card。
- 每张封面必须使用 `页面规划.md` / `content.json` 中确认过的封面最终可见中文文字。

建议差异维度：

- 构图：中心主视觉、左文右图、全景沉浸、抽象概念。
- 质感：摄影感、3D、插画、极简信息设计。
- 情绪：稳重、专业、现代、温暖、冲击。
- 信息密度：强标题、弱标题、强调副标题、强调场景。

## 用户可见产物

放在：

```text
阶段2_图片版PPT/封面风格候选/
```

建议文件：

```text
cover_option_A.png
cover_option_B.png
cover_option_C.png
cover_option_D.png
封面风格选择说明.md
```

用户只需要看封面图和说明，不需要看 style card、packet、prompt、hash、provider JSON。

`封面风格选择说明.md` 应说明：

- 候选 A-D 的差异。
- 每个候选适合哪种讲述方式。
- 每个候选如何延展到内页。
- 每个候选的风险。
- 主控建议。

## 运行过程文件

放在：

```text
_state/阶段2/cover_options/
  packets/
  prompts/
  results/
  style_cards/
  batches/
  api_calls/ 或 image_gen_calls/
  api_outputs/ 或 image_gen_outputs/
  api_batch_runs/
  selection/
```

其中：

- `packets/` 放生图任务包，包含 `image_generation_route`。
- `prompts/` 放四张封面的 final prompt。
- `results/` 放 provider 路线、证据和结果记录。
- `results/` 还必须记录实际尺寸、目标尺寸、偏好尺寸、`meets_preferred_size` 和 `size_warnings`。
- `style_cards/` 放四张候选的设计策展资产。
- `selection/` 放用户选择记录。

## 用户选择后

用户选择一个封面方向后，主控大模型必须沉淀：

```text
_state/阶段2/deck_style.json
_state/阶段2/layout_intent.json
```

`deck_style.json` 记录视觉系统。

`layout_intent.json` 记录版式意图和全局布局规则。

没有用户选择和这两份主控资产，不进入全套整页图片生成。

如果选中封面候选的中文文字、构图、证据链和 canonical 策略都通过主控检查，默认直接将该图转正为阶段2正式封面页，不再二次生成：

```text
阶段2_图片版PPT/img/slide_XXX.png
_state/阶段2/results/slide_XXX.json
```

转正后的正式 result 必须是 `purpose=full_slide`，并保留原 `cover_option` 的 `image_generation_route`、对应结果 ID、对应 evidence path、`parallel_batch_path`、`image_sha256`，额外记录：

```json
{
  "promoted_from_cover_option": true,
  "selected_cover_option": "A",
  "cover_option_result_path": "_state/阶段2/cover_options/results/cover_option_A.json",
  "cover_option_image_path": "阶段2_图片版PPT/封面风格候选/cover_option_A.png"
}
```

只有以下情况才重做封面：用户明确要求“风格可以但封面重做/微调”，或主控 QA 发现选中候选有乱码、伪字、文字与阶段1不一致、重要构图错误、证据链缺失、尺寸策略不可追溯、低于 2K 且主控判断会影响观感等问题。

## prompt 输入

封面候选 final prompt 应合并：

- 阶段1封面页最终可见中文文字。
- `design_contract.json` 的路线、受众、审美意图和封面候选策略。
- 对应 `style_card` 的构图、媒介、色彩、字体和风险约束。
- `通用视觉美学规范.md` 的禁止项。

如果旧项目缺少 `design_contract.json`，runtime 可以保留旧 A-D fallback；新项目不应依赖 fallback。

## 禁止事项

- 不让 runtime 自动选择封面。
- 不把四张封面候选整组直接打进图片版 PDF。
- 不把未选中的封面候选转正为正式页面。
- 不在选中封面已质量通过时，为进入阶段2B而默认二次生成封面。
- 不用本地渲染、fixture、source replay 冒充正式封面。
- 不改用本地渲染、浏览器截图、旧图复制、ImageGen/image2 等未入账路线；官方路线只能使用 Codex 内置 `image_gen` 并记录 evidence。
- 不把四张封面整组无 batch manifest 地随意生成；中转 API 路线不能整组串行逐张跑。
- 不把封面候选 prompt 放进用户可见目录。
- 不把 style card 放进用户可见目录。
- 不因为某张封面好看就忽略用户选择。
- 不让封面候选新增 `final_visible_text` 之外的标题、副标题、英文标签或装饰性文字。
