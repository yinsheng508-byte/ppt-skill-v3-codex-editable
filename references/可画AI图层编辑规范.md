# 可画 AI 图层编辑规范

## 能力边界

当用户提供 Canva/可画编辑页链接，并使用 `/canva编辑`、`/可画编辑` 或 `/可画AI编辑` 时，控制用户浏览器逐页点击 `AI图层`，把整页 AI 图片转换成可编辑 Canva 元素。

这是 Canva 页面内后处理动作，不等同于阶段3正式可编辑 PPTX 路线；不要写入 PPT 项目阶段状态、交付 manifest 或阶段切换决策。

## 实测结论

稳定、较快的路线是：

1. 使用 Chrome/Browser 插件连接用户 Chrome 登录态。
2. 如果认领已打开的重 Canva 标签页很慢或掉线，直接新建受控标签页打开同一 Canva edit 链接；同一 Chrome 登录态可继续编辑同一设计。
3. 用底部页码按钮打开 `input[aria-label="转至页面"]`，直接跳页；不要依赖横向缩略图滚动。
4. 每页只做一次 DOM 状态读取、一次主图点击、一次工具栏 `编辑`、一次 `AI图层` 点击；不逐页截图。
5. 每 1-2 页一组执行并汇报进度；Canva 页面较重时避免一次跑完整 26 页导致浏览器控制超时。

## 推荐执行器

优先使用被动执行器：

```js
const skillRoot = "/absolute/path/to/current-ppt-skill"; // 使用当前 Skill 根目录，不要跨安装位置硬编码
const { installCanvaAiLayerRunner } = await import(`${skillRoot}/scripts/runtime/canva_ai_layer_runner.mjs`);
const runner = installCanvaAiLayerRunner(tab);
const result = await runner.processRange(3, 26);
```

执行器只操作传入的 `tab` 和显式页码范围，不选择浏览器、不创建项目状态、不导出、不分享。主控大模型仍负责选择标签页、决定起止页、处理阻断和向用户汇报。

## 快速流程

1. 连接用户 Chrome；优先使用 Browser/Chrome 插件。
2. 找到或打开 Canva edit 链接，确认标题、链接和页码文本，例如 `1/26`。
3. 根据用户口径确定起始页。默认从第 1 页；如果用户说明前几页已成功，就从指定页继续。
4. 调用执行器按小批次跑页码范围。
5. 每批检查返回结果：`ai_layer_clicked`、`already_converted_or_ai_layer_missing`、保存状态、当前页码。
6. 末尾确认最终页码和 Canva 保存状态，通常应为 `已保存所有更改`。

## 单页核心动作

每页固定动作：

1. 用页码输入框跳到目标页，并确认 `当前页/总页数`。
2. 点击画布中的最大图片区域。
3. 点击顶部素材工具栏里的 `编辑`。
4. 确认左侧出现 `编辑图片`。
5. 点击左侧工具里的 `AI图层`。
6. 等 2 秒，再进入下一页。

## 已转换判定

以下情况可记录为已完成，不要反复拆：

- 用户确认该页已经点过。
- 点击画布后选中的是文字、图标、卡片、列表行等小图层，而不是整页大图片。
- 打开 `编辑图片` 后找不到 `AI图层` 卡片，但页面已经呈现可选小图层。

如果 `AI图层` 卡片仍存在，点击一次通常是安全的；点击后如果页面保持在小图层可选状态，也记录为已完成。

## 阻断与降级

遇到以下情况暂停汇报：

- 登录、验证码、权限不足、风控验证。
- 付费/试用弹窗阻断 AI 图层操作。
- Canva 顶部出现保存失败。
- 页码、工具栏 `编辑`、`编辑图片` 或 `AI图层` 连续两次无法稳定识别。
- Chrome 插件实例反复掉线，且新建受控标签页也失败。

降级顺序：

1. 已打开标签页卡住时，新建受控标签页打开同一 edit 链接。
2. DOM 点击失败时，先重新选中主图，再重开 `编辑图片` 面板。
3. 一次跑多页超时时，改成单页执行。
4. 系统级鼠标点击只有在已有辅助访问权限时才使用；不要要求用户临时改权限，除非用户明确愿意。

## 汇报口径

完成后汇报：

- 设计标题或链接。
- 总页数。
- 成功页、已跳过/已转换页、失败页。
- 最终停留页码和 Canva 保存状态。
- 如中途暂停，说明停在第几页、已完成到第几页、阻断原因和下一步继续页。
